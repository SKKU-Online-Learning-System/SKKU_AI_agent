이번 단계의 목표는 관리자와 교수자가 실제 운영에 필요한 최소 기능을 사용할 수 있게 하고, 전체 서비스를 테스트 가능한 MVP 상태로 완성하는 것이다.

구현해야 할 기능:

1. 관리자 대시보드
   - 전체 과목 수
   - 전체 사용자 수
   - 전체 질문 수
   - 일자별 질문 수
   - 과목별 사용 횟수
   - 과목별 사용자 수
   - 과목별 자료 업로드 수

2. 교수자 대시보드
   - 담당 과목 목록
   - 과목별 업로드 자료 수
   - 과목별 질문 수
   - 최근 질문 로그
   - 자주 등장한 질문 키워드 또는 단순 빈도 분석

3. 로그 조회 기능
   - 관리자는 전체 로그 조회 가능
   - 교수자는 담당 과목 로그만 조회 가능
   - 학생은 본인 대화 이력만 조회 가능
   - 기간, 과목, 사용자 기준 필터링을 지원해줘.

4. 기본 통계 API
   다음 API를 만들어줘.
   - 전체 서비스 통계
   - 과목별 통계
   - 교수자 담당 과목 통계
   - 학생 본인 사용 통계

5. UI 정리
   - 학생, 교수자, 관리자 메뉴를 역할에 따라 다르게 보여줘.
   - 각 화면에 로딩 상태, 오류 상태, 빈 상태를 추가해줘.
   - 답변 출처 영역과 경고 문구를 보기 좋게 정리해줘.

6. 테스트 데이터
   - 로컬 개발용 seed 데이터를 만들어줘.
   - 예시 사용자:
     - admin
     - professor
     - student
   - 예시 과목:
     - 인공지능개론
     - 소프트웨어공학
   - 예시 강의자료 또는 샘플 텍스트를 추가해줘.

7. 테스트
   다음 흐름이 동작하는지 확인할 수 있게 테스트 방법을 정리해줘.
   - 관리자가 과목 생성
   - 교수자가 자료 업로드
   - 자료가 지식베이스로 처리됨
   - 학생이 과목 선택 후 질문
   - AI가 출처 포함 답변 생성
   - 로그가 저장됨
   - 교수자가 과목별 로그 확인
   - 관리자가 전체 통계 확인

8. README 업데이트
   README에 다음 내용을 정리해줘.
   - 프로젝트 소개
   - 기술 스택
   - 로컬 실행 방법
   - 환경변수 설정
   - DB 마이그레이션 방법
   - seed 데이터 생성 방법
   - 테스트 계정
   - 주요 API
   - MVP 기능 목록
   - 아직 구현되지 않은 고도화 기능

9. 코드 품질
   - 중복 코드를 정리해줘.
   - 타입 에러를 해결해줘.
   - 린트 에러를 해결해줘.
   - 주요 함수에는 간단한 주석을 추가해줘.
   - 보안상 위험한 하드코딩 값은 환경변수로 분리해줘.

수용 기준:

- 로컬에서 README만 보고 서비스를 실행할 수 있어야 한다.
- admin, professor, student 계정으로 각각 로그인해 역할별 기능을 확인할 수 있어야 한다.
- 강의자료 업로드부터 RAG 답변 생성까지 전체 흐름이 동작해야 한다.
- 답변에는 출처가 표시되어야 한다.
- 로그와 통계가 관리자/교수자 화면에 표시되어야 한다.
- MVP 미구현 기능은 TODO 또는 Roadmap에 정리되어야 한다.

작업 후에는 다음을 알려줘:

- 최종 구현 기능 목록
- 실행 방법
- 테스트 계정
- 확인해야 할 주요 시나리오
- 남은 TODO
- 고도화 제안
