# 학습 상태 시제품: 다중 턴 검증

## 판정

현재 Qwen3.5-9B 비추론 설정에서 이 최소 시제품은 채택하지 않는다. 학생이 실제로 한 설명을 저장하는 데에는 성공했으나, 저장된 상태를 적절한 다음 교육 행동으로 연결하는 데 실패했다. 상태 저장만 추가하면 대화 품질이 해결된다는 가설은 이번 시험에서 지지되지 않았다.

## 시제품

기존 음성 정책과 LLMService를 재사용한다. 모델 교체·추가 학습·추가 LLM 호출·발화별 키워드 조건문은 없다. 후보만 finish_turn에 demonstrated(개념 하나와 학생 발화의 인용)를 반환한다. 프로그램은 인용이 실제 이번 학생 발화에 포함되는지 검사하고, 개념별 최신 근거를 다음 턴에 전달한다. 현재 주제·직전 교사 발화·간단한 학습 목표 순서도 함께 제공한다.

인용 일치 검사는 출처 검사이지 이해 여부의 의미 검증이 아니다. demonstrated는 모델이 평가한 잠정 기록이며 객관적으로 검증된 숙련도를 뜻하지 않는다. 의미가 맞는지는 이번 원문 검토에서 별도로 확인했다. 예컨대 모델이 “응”을 근거로 제출하면 단순 인용 검사만으로 막을 수 없으며, 이를 실패로 평가하도록 설계했다.

## 본 비교

- 모델: Qwen3.5-9B, 음성 프로필, thinking 비활성, 출력 한도 320토큰.
- 8개 학생 발화가 이어지는 세션 × 기준선/상태 후보 × 2회 = 32턴.
- 발화 순서: 처음 배우기 → 그러게 → 응 → 쉬운 예 요청 → 같은 입력이면 반반 → 같은 이유 설명 → 소프트맥스 요약 → 중단.
- 실제 생성된 교사 답변을 각 조건의 다음 대화 이력에 추가한다. 두 조건의 이력은 결과적으로 달라진다. 기존 12메시지 이력 제한을 유지한다.
- 학생 발화는 고정 합성 시나리오다. 교사의 실제 질문에 적응하는 사람이나 학생 시뮬레이터가 아니므로 자유 대화 성공률이나 학습 효과로 해석하지 않는다. 학생의 뒤쪽 정답은 미리 작성된 것이지 교사 덕분에 학습한 결과가 아니다.
- 본 비교에서는 두 조건 모두 finish_turn만 제공한다. 기준선도 이 점에서 운영 구성과 다르다. 실제 검색·시각자료 렌더링·ASR·TTS는 실행하지 않는다. 요청된 시각자료가 표시됐다고 이력에 추가하지 않는다.
- 일반 텍스트 응답은 기존 recover_plain_turn으로 복구한다. 검증 실패 시 시험용 실패 문장을 이력에 넣고 다음 턴을 계속한다. 운영의 전체 재시도/도구 루프는 재현하지 않는다.

## 결과

### 저장은 됐지만 발화는 따르지 않았다

후보의 두 세션 모두 “그러게”와 “응” 뒤의 상태는 빈 기록이었다. 그러나 “그러게”에는 2/2회 “맞습니다”라고 답했다. 한 세션은 학생이 아직 모른다고 하는 단계에서 입력 세 개의 확률 계산을 요구했고, 다른 세션은 같은 상수를 더해도 결과가 변하지 않는 이유를 물었다. 근거가 없는 이해 판정이 기록에서는 억제됐지만 발화와 난이도 선택에서는 남았다.

### 확인된 내용을 다시 물었다

학생이 두 입력이 같으면 각각 0.5라고 답하면 후보는 2/2회 equal 근거를 정확히 저장했다. 그런데 곧바로 입력 2와 2 또는 1과 1의 출력이 무엇인지 다시 물었다. 뒤이어 학생이 이유를 설명하면 인용을 갱신했지만 다시 2와 3의 소프트맥스 수치로 넘어갔다. 단순한 반복과 의도적인 이해 재확인을 완전히 구분할 수는 없지만, 명시한 “확인한 내용은 반복하지 않기”와 맞지 않았다.

### 요약 뒤에도 계산으로 돌아갔다

후보는 학생의 올바른 최종 요약을 실제 인용과 함께 2/2회 저장했다. 한 세션은 normalization, 다른 세션은 definition으로 분류했다. 둘 다 적절한 근거였으나 그 뒤 다시 2와 3의 수치가 나오는 이유를 물었다. 기준선도 두 세션 모두 추가 적용을 요구했다. 요약 후 질문이 언제나 잘못은 아니지만, 이 시나리오의 마무리 목표가 개선됐다는 근거는 없다.

### 종료와 오류

명시적인 중단 요청은 양쪽 두 세션 모두 새 과제를 요구하지 않고 마쳤다. 후보의 한 종료 답변은 개념 설명 근거만으로 “계산 방법”까지 이해한 것처럼 과장했다.

기준선에서 220자 초과 검증 실패가 1/16턴 발생했고 후보는 0/16턴이었다. 기준선 두 번째 세션의 그 이후 결과에는 실패 문장의 영향이 있어 엄밀한 짝 비교로 해석하지 않는다. 후보의 부적절한 망설임 대응은 양쪽 세션에서 이 오류 이전부터 관측됐다.

단일 호출과 검증까지의 시간 중앙값은 기준선 3.3295초, 후보 4.378초였다. 상태 필드와 프롬프트가 늘고 출력/이력이 달라졌으며 부하·캐시를 통제하지 않았다. 인과적 지연 차이나 음성 첫 재생 시간으로 해석하지 않는다.

## 초기 실행을 분리한 이유

검색 도구를 포함한 초기 32턴에서 두 조건 모두 쉬운 예 요청을 웹 검색으로 처리했다. 이 초기 시험기는 검색을 실행하지 않으므로 시험용 실패 문장이 후속 이력에 들어갔다. 이를 학습 상태 효과와 섞지 않기 위해, 양쪽 모두 검색을 제외한 본 비교를 별도 실행했다. 초기 결과를 삭제하거나 성공 사례로 재분류하지 않았다.

## 조치

운영 설정과 애플리케이션 코드는 변경하지 않았다. 테스트 코드에만 시제품을 남겼다. 현 단계에서 더 복잡한 상태 관리나 두 번째 판단 호출을 운영에 추가할 근거는 없다. 이번 결과는 이 특정 시제품과 현재 모델·비추론 설정의 한계를 보여 주며 모든 상태 기반 튜터 구조의 불가능성을 뜻하지 않는다.

## 재현 및 검증

`PYTHONPATH=apps/backend:scripts .venv-app/bin/python scripts/eval_voice_learning_state.py`

- 본 비교: `voice-learning-state-finish-only-20260910.jsonl`
- 초기 실행: `voice-learning-state-20260910.jsonl`
- 각 파일은 입력, 도구 원문, 상태 전후, 시간, 오류를 보관한다. 민감한 학생 자료나 API 키는 없다.
- 본 비교의 32개 고유 턴, 세션별 순서, 상태 연속성, 인용 출처, 수긍 단계에서 상태가 비어 있음, 최종 상태에 실제 학생 근거가 남음, 알려진 오류 한 건을 검사했다. Ruff 및 diff 검사 통과.

소수 시나리오를 단일 AI가 비블라인드로 검토한 결과다. 자연스러움이나 교육 효과의 일반적인 성능 점수로 사용하지 않는다.
