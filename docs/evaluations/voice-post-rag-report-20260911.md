# 멀티모달 검색 적용 후 음성 에이전트 재평가 — 2026-09-11

강의 도표의 값은 정확히 읽었지만 자연스러운 소크라틱 대화는 아직 부족하다. 현재 로컬 `.env`의 VAD 임계값 1.0은 시험 음성을 감지하지 못했고, 텍스트가 들어온 뒤에도 실제 자료를 읽고 답변을 준비하는 데 중앙값 21.7초가 걸렸다. 운영 모델·프롬프트·설정은 이번 평가에서 변경하지 않았다.

## 조건과 범위

- 음성 생성 모델: 기존 `Qwen/Qwen3.5-9B`, thinking 비활성화. 자료 이미지 판독도 동일 모델. 임베딩: `Qwen/Qwen3-VL-Embedding-2B:2048`.
- 실제 Transformer PDF 3개, 검색 가능한 이미지 페이지 82개. 매 턴 실제 강의자료 검색. 실제 자료 평가에서 기억 조회와 백그라운드 기억 저장만 비활성화했다. 기존 운영 이력·학생 데이터는 수정하지 않았다.
- 고정 근거 대조군 10종 × 2회 = 20턴: 실제 음성 LLM, 검색·웹·기억·TTS는 기존 평가 fixture. 기존 증상이 남는지 확인하는 용도다.
- 실제 RAG 평가 12종 × 2회 = 24턴: 이미지 판독 및 운영 voice brain 실제 실행. ASR/TTS와 지연 시각화 생성은 이 24턴에 포함되지 않는다.
- 모델 요청은 다른 평가와 겹치지 않게 순차 실행했다. 소규모 개발 평가이며 실제 학생 학습효과나 일반적인 성공률을 추정하지 않는다.
- 운영 출력은 아직 `finish_turn` 필수 도구와 220자 검증을 사용한다. 이전 plain-output 실험이 운영에 적용된 것으로 간주하지 않았다.

고정 근거 대조군도 망설임 4/4회 오인, 대기 요청 2/2회 불필요한 질문을 재현했다. 20턴 오류 0, 중앙값 2.911초. 자동 문자열 경고가 없던 8/20을 교육적 성공률로 쓰지 않는다. 실제 자료 평가와 근거·호출 경로가 달라 속도 A/B 비교로 해석하지 않는다.

## 음성 입력 설정 문제

현재 `.env`는 `VAD_THRESHOLD=1`, 예제 설정과 코드 기본값은 0.5다. 현재 설정으로 합성 입력을 실시간 20ms 프레임으로 보내고 180초 기다렸으나 `SessionReady` 외 발화 시작·인식·응답 이벤트가 없었다. 동일 WAV를 실제 Silero에 재입력하면 임계값 1.0에서 발화 시작/완료 0/0회, 0.5에서 1/1회다. 이것이 모든 실제 녹음에서의 실패율을 뜻하지는 않지만 현재 시험의 입력 차단 원인은 명확하다.

운영 `.env`는 유지하고, 별도 평가 프로세스에만 `VAD_THRESHOLD=0.5`를 지정해 이후 음성 경로를 측정했다. 이 결과는 현재 설정 그대로의 성능과 구분한다.

## VAD 0.5로 분리 측정한 음성 경로

합성 학생 음성 → 실제 Silero VAD → 실제 ASR → 실제 자료 검색/판독 → 9B 답변 → 스트리밍 TTS를 실행했다. 3/3회 오디오 생성 완료. 브라우저 WebSocket·스피커 재생, 실제 사람 녹음, 끼어들기는 이번 범위가 아니다. 음질/MOS도 평가하지 않았다.

| 합성 입력 | ASR | VAD 종료 → 첫 오디오 | 입력 파일 마지막 프레임 → 첫 오디오 | 출력 오디오 길이 |
|---|---:|---:|---:|---:|
| 인과 마스크 삼 번 행 질문 | 0.978초 | 20.278초 | 20.692초 | 17.899초 |
| 설명을 들어도 모르겠음 | 0.731초 | 28.824초 | 29.331초 | 23.298초 |
| 잠깐 기다려 주세요 | 0.535초 | 31.745초 | 32.275초 | 4.202초 |

VAD 종료 기준 첫 오디오 중앙값은 28.824초다. 이 기준은 발화 종료 감지까지의 침묵 대기를 제외하므로 실제 사용자가 느끼는 대기보다 짧다. 입력 프레임 기준 역시 파일에 포함된 끝부분 무음을 포함하는 근사값이다.

- 숫자 의미 오류: 입력 “삼 번 행” → ASR “세 번 행” → 답변 “세 번째 행 (인덱스 2), 0~2까지”. 사용자가 의도한 번호 3과 서수 세 번째를 혼동했다. 텍스트 도표 검색이 맞더라도 음성 입력에서 지시 대상이 달라질 수 있다.
- 막힘: 정답 설명을 길게 반복하고 “더 자세히 설명해 드릴까요?”로 끝났다. 출력 오디오 약 23초로 사고를 유도하기 전 설명량도 크다.
- 대기: “네, 잠시 기다려 드릴게요. 무엇을 도와드릴까요?”가 음성 경로에서도 재현됐다.
- 최종 텍스트 이벤트에서 첫 오디오까지는 각각 약 309/324/317ms였다. 이 사례의 주 병목은 첫 TTS 청크 생성보다 앞선 단계다.
- 현재 `tts_ms` 계측은 speech pipeline 시작부터 재며 RAG와 답변 대기까지 포함한다. 이를 순수 TTS 추론 시간이나 TTS RTF로 해석하면 안 된다. `llm_ttft_ms` 역시 현재 코드에서는 첫 토큰 시간이 아니라 답변 LLM 전체 시간이다.

[음성 경로 원본](voice-post-rag-audio-vad05-20260911.jsonl)에 이벤트·ASR 결과·지연·오디오 파일 경로를 저장했다. WAV는 `/tmp/voice-post-rag-audio/`에 있다. 원래 임계값 실험에 사용한 파일은 `vad-baseline-input.wav`로 보존했다. 이 세 사례에서 시각화 도구 출력 이벤트는 없으므로 시각화 생성 품질이 통과했다고 주장하지 않는다.

## 실제 이어지는 4턴 대화

고정된 직전 질문을 매번 주는 평가와 별도로, 실제 응답을 읽고 다음 학생 말을 정해 같은 이력을 이어갔다. 4턴 모두 실제 강의자료를 검색했고 오류는 없었다. 중앙값 27.998초, 최대 34.672초. 이 수치는 위 24턴 통계에 합치지 않았다.

| 턴 | 학생 | 에이전트의 진행 |
|---|---|---|
| 1 | 미래 정보를 가린다는 뜻을 질문 | 예시와 목적을 설명하고 종료. 확인 질문 없음 |
| 2 | 미래도 보면 예측이 더 정확하지 않느냐고 질문 | 학습과 추론의 차이를 직접 설명하고 종료 |
| 3 | “실제로 예측할 때는 다음 단어를 모르니까 가리는 거구나. … 쉬운 질문 하나 해줘” | 이해를 인정하고 같은 설명 반복 후 “인과 마스크가 어떤 역할을 할까요?”라고 질문 |
| 4 | “아직 예측해야 하는 미래 단어를 미리 못 보게 막는 역할” | 정답 인정 후 다시 설명. 다음 적용 문제 대신 표를 설명해 주겠다고 제안 |

이 대화에서는 정답 판단 자체는 적절했다. 그러나 학생이 이유를 설명한 뒤에도 같은 역할을 다시 묻고 설명을 반복했다. 자발적인 작은 추론 질문과 새로운 상황에 적용하는 진행이 약하다. 실패를 모든 응답이 틀렸다는 뜻으로 해석하지 않는다. [연속 대화 원본](voice-post-rag-dialogue-20260911.jsonl)에 이전/이후 전체 이력과 요청을 저장했다.

## 개선 우선순위

1. **발화 감지 설정 복구와 확인.** 현재 로컬 임계값 1.0을 먼저 바로잡아야 한다. 0.5는 이번 파일에서 확인된 기본값이지 모든 마이크 환경의 최적값은 아니다. 실제 마이크 입력으로 종료 감지와 끼어들기까지 확인한다.
2. **매 턴 자료 확인은 유지하면서 반복 이미지 판독을 줄인다.** 동일 페이지의 변하지 않는 표·라벨·수치를 색인 시 추출해 원본 버전과 함께 보관하고 재사용하는 방향이 우선이다. 새 질문에 필요한 시각 정보가 기존 근거에 없을 때만 원본을 다시 읽는다. 현재 판독은 질문에 종속되므로 앞선 답을 무조건 재사용하는 캐시는 부적절하다. 검색을 생략하거나 학생 발화를 패턴 매칭할 필요는 없다.
3. **말하기와 출력 계약의 부담을 줄인다.** 필수 `finish_turn`과 엄격한 220자 제한 때문에 유효 답변이 사라지는 실패를 제거하고, 전체 구조화 출력 완료를 기다리는 경로를 검토한다. 발화와 화면 동작을 분리하는 기존 실험을 동일 근거·이력으로 다시 비교한다. 형식 제거만으로 교수법이 개선된다고 가정하지 않는다.
4. **소크라틱 행동을 실제 이어지는 대화로 검증한다.** 망설임과 정답을 의미로 구분하고, 막히면 더 작은 판단 질문 하나를 내며, 학생이 이유를 설명하면 다음 개념으로 진행하고, 대기 요청은 존중하도록 최소 지침을 검증한다. 새 모델이나 규칙 기반 발화 분류기는 도입하지 않는다. 음성의 행 번호/서수 혼동도 지시 대상 확인 사례에 포함한다.

이번 턴에서 추가한 것은 평가 스크립트와 결과 문서다. 운영 코드·모델·프롬프트·`.env` 변경은 하지 않았다. 다음 수정의 효과는 동일 사례와 음성 지연으로 다시 검증해야 한다.
