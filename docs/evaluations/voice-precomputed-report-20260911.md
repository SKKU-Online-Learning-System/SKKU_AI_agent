# 강의자료 사전 판독 적용 — 2026-09-11

음성 모델 Qwen/Qwen3.5-9B와 임베딩 Qwen/Qwen3-VL-Embedding-2B는 유지했다.

## 변경

- 업로드 201 응답 후 서버 BackgroundTasks에서 페이지 렌더링·전체 이미지 판독·임베딩을 수행한다. 원문, JPEG, 질문에 독립적인 `page_evidence`를 동일 청크로 저장한다. 모든 페이지 성공 후 검색 가능 상태가 된다.
- 매 턴 자료 검색은 유지하되 저장된 해석을 읽는다. 이전 버전의 해석 없는 청크만 호환용 실시간 판독을 사용한다.
- 원본 재판독은 별도 페이지 inspect API로 분리했다. 현재 과목의 완료된 자료만 접근할 수 있다. 추가 판독은 공유된 사전 해석을 덮어쓰지 않는다. 대화 모델의 도구는 늘리지 않았다.
- 교수자 자료 목록과 음성 설정 화면에서 분석 상태를 5초마다 갱신한다. 업로드와 별도의 중복 처리 요청은 제거했다.
- 220자 출력 계약, 소크라틱 지침, VAD 설정은 이번 수정 범위에 포함하지 않았다.

## 검증

백엔드 345개, 프런트엔드 78개 테스트 통과. Ruff, TypeScript, ESLint, production build 통과.
추가 검사는 반복 검색 시 판독 호출 없음, 도표 수치 보존, 과목/페이지 접근 제한, 명시적 원본 조회 API의 출처·오류 응답, 재처리 실패 시 기존 청크 보존, 업로드 백그라운드 성공/실패 상태 저장을 확인한다.

단위 테스트는 실제 모델 서버를 사용하지 않는다. 아래 실측은 별도로 실제 모델 서버를 사용한다.

## 운영 범위

새 컬럼은 Alembic `20260911_0007`로 추가한다. 기존 자료는 `scripts/reindex_materials.py --course-id …`로 다시 처리해야 반복 이미지 판독이 제거된다.
업로드 처리는 앱 프로세스 내 백그라운드 작업이다. 강제 종료 후 자동 복구하는 분산 작업 큐는 아니다. 정상 처리 오류는 failed로 남고 기존 재처리 기능을 사용한다. 준비 중인 자료는 대화 검색 대상에 들어가지 않는다.

## 실제 자료 처리

Transformer PDF 3개, 총 82페이지의 사전 판독·재색인을 완료했다. 실행은 04:48:43~05:00:34 UTC, 약 11분 51초였다. 파일별 완료 페이지는 28/30/24다. 모두 completed이며 모든 페이지에 `page_evidence`가 존재한다. 판독 최대 길이는 3,235자로, 이번 자료의 판독 결과 자체는 음성 근거의 6,000자 제한 안에 들어간다.

인과 마스크 표 3번 행의 0~3 가시 영역, 사인 위치 인코딩의 Depth/Position 축, MHA/GQA/MQA의 KV 헤드 8/4/1을 저장된 판독에서 확인했다. [처리 상태와 판독 예시](precomputed-corpus-20260911.json). 모든 문장·그림의 무오류 해석을 검증한 것은 아니다.

## 채택하지 않은 원본 재확인 도구

처음에는 저장된 해석에 없는 세부 정보만 확인하도록 `inspect_course_page`를 음성 모델에 제공했다. 같은 24턴에서 16번 원본을 다시 읽었고, 이미 근거가 있는 인과 마스크·좌표축에서도 호출됐다. 중앙값 9.658초, 응답 검증 오류 1건이었다.

따라서 이 도구를 운영 대화 경로에서 제거하고 원본 재판독을 별도 API로 분리했다. [실험 원본](voice-precomputed-live-20260911.jsonl)은 최종 구현의 결과가 아니다. 최종 구현에서는 저장된 근거가 부족하면 그 한계를 답변해야 하며, 자동 원본 재판독을 제공한다고 주장하지 않는다.

## 자동 재판독 제거 후 24턴 비교

이전 실제 강의자료 평가와 같은 입력·이력 12종을 각각 2회 실행했다. 모델과 임베딩 모델은 동일하며, 새로 재색인한 페이지의 저장된 해석을 사용한다. 실제 GPU 서버 호출을 순차 실행했으며 학생 기억 읽기/저장만 격리했다. ASR/TTS는 이 표에 포함하지 않는다.

| 지표 | 이전 질문별 판독 | 사전 판독 사용 |
|---|---:|---:|
| 응답 준비 중앙값 | 21.742초 | 7.296초 |
| 응답 준비 p90 | 30.273초 | 11.735초 |
| 응답 준비 최대 | 31.865초 | 13.078초 |
| 자료 단계 중앙값 | 17.016초 | 1.208초 |
| 답변 LLM 중앙값 | 4.890초 | 6.076초 |
| 대화 중 이미지 판독 횟수 | 48회 | 0회 |

중앙값 기준 전체 약 66%, 자료 단계 약 93% 감소다. 서버·생성 변동을 포함한 개발 환경 관측이며 일정 지연을 보장하지 않는다. `finish_turn` 전체 검증 후 음성이 시작되는 기존 구조가 남아 있어 LLM 시간은 아직 크다.

[24턴 원본](voice-precomputed-final-20260911.jsonl). 예외로 끝난 턴은 0개였지만 RoPE 한 턴은 기존 출력 검증 재시도 후 사과 fallback이어서 내용상 성공이 아니다. 오답을 “맞아요”로 시작하거나, 대기 요청에 추가 질문하는 교수법 문제도 남았다.

이 평가에서 MHA/GQA/MQA 한 응답이 GQA 값 헤드 수를 잘못 답했다. 저장된 판독에는 8/4/1 수가 있었으나 패널별 이름이 반복 목록과 명확히 연결되지 않았다. 사전 판독 지침에 “병렬 도표는 이름별 별도 절로 나누고 모든 수치와 연결 관계를 패널에 명시적으로 연결”하도록 보완했다. 첫 보완 지침으로 재처리 중 판독 실패가 발생해 기존 청크를 보존한 채 failed 상태를 기록했고, 간결한 지침으로 Part3 재처리를 완료했다. 재처리 후에는 MHA/GQA/MQA 제목별로 키·값 개수와 Query 연결 관계가 명확히 구분돼 저장됐다. 이 표는 그 레이아웃 보완 전 전체 평가이며, 이후 영향받는 사례를 별도로 확인한다.

## 도표 배치 보완 후 영향 사례 재검사

Part3 전체 재처리 성공 후 MHA/GQA/MQA, RoPE 전환, 기회비용 근거 없음의 3종을 각각 2회 재실행했다. 6턴 모두 응답을 생성했고 이미지 판독 호출은 0회였다. 헤드 수는 두 번 모두 MHA 8/8, GQA 4/4, MQA 1/1로 답했다. 기회비용 정의가 자료에 없다는 답도 유지됐다. [보완 후 6턴 원본](voice-precomputed-layout-20260911.jsonl).

6턴 중앙값은 9.774초다. 쉬운 종료/대기 사례가 없는 표본이므로 전체 24턴 중앙값과 직접 비교하지 않는다. 이것은 교수법 전체의 개선을 뜻하지 않는다.

## 실제 음성 경로

기존과 같은 합성 입력 3종을 VAD → ASR → 실제 RAG/9B → 스트리밍 TTS로 재실행했다. 운영 `.env`의 VAD 1.0은 변경하지 않았으며 평가 프로세스에만 0.5를 지정했다. 실제 학생 녹음, 브라우저 전송·스피커 재생, 음질 평가는 포함하지 않는다.

| 사례 | 이전 VAD 종료→첫 오디오 | 사전 판독 후 |
|---|---:|---:|
| 인과 마스크 행 질문 | 20.278초 | 11.245초 |
| 설명을 들어도 모르겠음 | 28.824초 | 10.017초 |
| 잠깐 기다려 주세요 | 31.745초 | 4.401초 |
| 중앙값 | 28.824초 | 10.017초 |

3/3회 오디오는 생성됐다. 최종 텍스트 이후 첫 오디오까지는 약 0.3초였다. VAD 종료 기준은 감지까지의 침묵 대기를 제외한다. 합성 파형과 답변 길이가 실행마다 달라 정밀한 음성 A/B 실험은 아니다.

**정확도는 별개다.** 인과 마스크 답변이 3번 행의 현재 위치 3번 열을 빠뜨렸다. 첫 입력에는 삼 번/세 번 인식 혼동이 있었고, 두 번째 막힘 사례도 3번 열을 누락했다. 저장된 표는 0~3에 체크가 있어 정확하므로, 근거를 답변으로 옮기는 모델 단계의 오류가 남은 것이다. 대기 요청에 추가 질문하는 문제도 남았다. 따라서 음성 출력 성공을 교육적 성공으로 해석하지 않는다.

[음성 원본·이벤트·WAV 경로](voice-precomputed-audio-20260911.jsonl). WAV는 `/tmp/voice-precomputed-audio-20260911/`에 저장했다. `tts_ms`와 `llm_ttft_ms`의 기존 계측 한계는 이전 보고서와 동일하다.
