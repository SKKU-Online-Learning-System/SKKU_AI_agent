# 발화 관계 명시 후보 검증

## 판정: 채택하지 않음

직전 교사 발화와 이번 학생 발화를 구분해서 제시해도 일반 답변 생성의 핵심 실패가 해결되지 않았다. 일부 명시적 망설임에는 개선이 있었으나 모호한 반응과 이해 상태 판단은 불안정했다. 운영 코드에는 적용하지 않았다.

## 조건

Qwen3.5-9B, 기존 음성 프로필과 도구·교육 지침·출력 한도 유지. 기존 평가기의 8사례 × 2조건 × 2회 = 32회. 조건별 순서를 고정 시드로 섞어 단일 요청씩 실행했다. 기준선도 이번에 새로 생성했다. 모든 사례는 기존 평가 fixture로, 미공개 독립 검증 세트는 아니다.

후보는 마지막 user 메시지만 수정한다. 직전 교사 발화와 이번 학생 발화를 JSON 데이터로 구분하고, 그 관계를 고려해 학생에게 다음 말을 하라는 짧은 요청을 붙인다. 원래 대화의 앞부분과 system의 자료·student_question은 그대로다. 따라서 발화의 반복, JSON 표현, 추가 지시 효과는 분리되지 않는다. 학생의 의미를 미리 분류하거나 정답 대응을 주입하지 않는다. 합성 입력만 사용하고 실제 학생 기록은 사용하지 않는다.

평가 기준은 모호한 반응에 정답 칭찬을 하지 않는지, 어려워하는 학생의 부담을 낮추는지, 수긍 후 반복하지 않는지, 정확한 답을 인정하는지, 오답을 수정하는지, 중단을 존중하면서 이해를 지어내지 않는지다. 단일 AI가 응답 원문을 비블라인드로 검토했다. 자동 검사 통과를 교육 품질 성공으로 간주하지 않는다.

## 결과

- **그러게:** 기준선·후보 모두 2/2회 “맞습니다”로 부적절하게 동의했다. 후보도 계산을 요구했다. 핵심 실패가 남는다.
- **아직 감이 안 잡혀:** 후보는 2/2회 “괜찮아요”로 시작하고 작은 값 비교 또는 같은 입력의 확률 질문으로 전환했다. 기준선은 이미 주어진 2와 3의 값을 다시 알려 달라고 2/2회 요구했다. 이 사례에서는 후보가 더 적절했다.
- **듣고 보니 그럴 듯하네:** 후보는 계산 또는 합 확인으로 이동했지만 한 번에 질문 둘을 던지거나 학습 수준 확인 없이 계산을 요구했다. 완전한 개선으로 판단하지 않는다.
- **말은 알겠는데 설명하라면 자신 없어:** 양쪽 모두 긴 설명을 이어갔다. 후보도 학생이 답할 수 있는 작은 확인 단계로 바꾸지 못했다.
- **정확한 요약:** 양쪽 모두 맞다고 평가했지만 2/2회 계산·추가 설명 과제를 제시했다. 마무리 개선은 확인되지 않았다.
- **둘 다 오십 퍼센트겠지:** 양쪽 모두 2/2회 정답으로 인정했다. 후보는 추가 질문을 붙였다. 학생 이해 수준에 맞는 구체성은 별도 과제다.
- **합력이 0이면 바로 멈춰요:** 양쪽 모두 2/2회 사실을 수정했다. 후보의 한 응답은 “다시 생각해 보세요”로 끝나 구체적 힌트는 없었다.
- **머리가 꽉 찼어. 나머지는 다음에 하자:** 양쪽 모두 중단은 존중했다. 그러나 후보 1/2회는 “네, 이해가 잘 되셨군요”라고 근거 없이 평가했다. 기준선 두 응답에는 이 오류가 없었다.

think_voice 전체 시간 중앙값은 기준선 3.403초, 후보 2.9845초였다. 워밍업 별도 분리·서버 부하 통제가 없고 출력 길이와 생성 경로가 달라 속도 개선으로 결론 내리지 않는다. 실제 ASR·TTS 지연은 포함하지 않는다.

## 결론의 범위

이전 의미 판별 실험에서 자료 표현이 도움이 됐다고 해서 실제 교육 답변 생성에서도 개선되는 것은 아니었다. 검증한 이 구체적인 입력 후보는 실패다. 모든 프롬프트 개선 가능성이나 모델 자체의 능력에 대한 일반적 부정은 아니다. 확인되지 않은 개선을 운영에 적용하거나 발화별 조건문을 추가하지 않았다.
