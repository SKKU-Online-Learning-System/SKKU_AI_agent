# 음성 출력 계약 분리 진단

## 결론

일반 텍스트 출력에서도 “그러게”에 부적절하게 동의했다. 따라서 finish_turn 도구나 JSON 생성만을 원인으로 볼 수 없다. 반면, 정확한 학생 요약을 의미 판별 과제로 제시할 때 대화 기록을 분석 대상 자료로 명시하면 판단이 달라졌다. 현재 모델의 문맥 해석은 과제 제시 방식에 민감하며, 도구 제거만으로 개선되지 않는다. “모델이 전혀 이해할 수 없다” 또는 “프롬프트만 고치면 해결된다” 중 어느 쪽도 입증하지 못했다.

## 실험 조건

Qwen3.5-9B 음성 프로필, thinking 비활성, 기존 설정의 temperature와 출력 한도 320토큰. 이전 실험에 저장된 동일한 합성 입력을 LLMService로 재생했다. 3사례 × 4조건 × 2회 = 24회, 추가 분석용 자료 표현 조건 6회로 총 30회다. 새로운 자료 검색·ASR·TTS·실제 학생 로그·운영 설정 변경은 없다.

조건:

- tools: 저장된 지침·도구(검색과 finish_turn) 그대로.
- finish_only: 도구 목록만 finish_turn 하나로 축소. 공급자 어댑터에 의해 tool_choice도 required에서 특정 함수 지정으로 바뀐다. 그러므로 검색 선택과 강제 함수 지정 효과는 서로 분리되지 않는다.
- plain: 같은 대화·자료·교육 정책에서 도구를 없애고 마지막 출력 지시를 220자 이하의 일반 텍스트로 교체. 출력 관련 지시도 바뀌므로 순수한 JSON 인코딩 효과만을 측정한 것은 아니다.
- interpret: 같은 user/assistant 메시지를 유지하고 시스템 지시를 학생 발화의 의미와 다음 교사 행동을 두 문장으로 판별하는 과제로 변경. 교육 답변과는 다른 과제이므로 직접 품질 점수로 비교하지 않는다. 자료는 제공하지 않는다.
- interpret_wrapped: 동일 판별 지시에서 대화 내용을 JSON 자료로 한 user 메시지에 넣고 분석 요청을 명시. 정보 내용은 같지만 역할 표현과 메시지 구조가 바뀐다.

모든 결과는 첫 LLM 호출의 원문이다. production brain의 검증·재시도·말하기 파이프라인을 거치지 않아 이전 전체 brain 지연과 비교하지 않는다. 모델별 속도 비교도 이번 목적이 아니다. 두 실행의 파일별 종료 여부를 확인했으며 소수 반복이므로 부하 통제나 유의성 판단을 하지 않았다.

## 응답 검토

### 망설임

“그러게”에 tools와 plain 모두 2/2회 “맞아요/맞습니다”로 응답했다. plain은 질문에 답하지 않은 학생에게 정답 동의를 한 뒤 교과 설명을 이어갔다. finish_only는 2/2회 intent를 social로 분류하고 계산을 제안했다. 표현만 바뀌었을 뿐 막힌 학생에게 쉬운 힌트를 제공하는 대응이 아니다.

interpret는 한 번 모호성을 인정했지만 다른 한 번은 설명을 수용하는 동의로 해석했다. interpret_wrapped도 한 번은 명확한 답이 아닌 모호한 반응이라고 판단했고, 다른 한 번은 질문에 대한 동의로 해석했다. 불확실한 발화 처리의 불안정성이 남는다. “그러게” 자체가 항상 무지를 뜻하지 않으므로, 성공 기준은 강제적인 위로 문구가 아니라 이해가 확인되지 않았다는 점을 존중하고 부담 낮은 확인을 하는 것이다.

### 가벼운 수긍

tools와 finish_only는 이미 설명한 softmax 원리를 반복하는 응답을 냈다. plain은 계산 과제로 전환했으나 반복 두 번 중 한 번은 정답 수치를 먼저 주었다. 도구를 없애면 교육 행동이 자동으로 좋아진다는 증거는 아니다.

interpret는 두 번 모두 이해 정도를 더 확인해야 한다고 판단했다. interpret_wrapped는 두 번 모두 긍정적인 반응으로 해석했으며 한 번은 이해가 되었다고 서술했다. 자료 표현 변경도 모든 사례에서 일관된 개선은 아니다.

### 정확한 학생 요약

교사가 한 문장 요약을 요청하고 학생이 지수값을 전체 지수값의 합으로 나눈다고 정확히 설명한 사례다.

interpret는 2/2회 학생 역할을 잘못 해석했다. 각각 “설명을 요청하고 있다”, “직전 발화와 직접 관련 없는 새로운 개념을 설명하려 한다”고 답했다. 반면 interpret_wrapped는 2/2회 교사의 요청에 맞는 정확한 요약임을 인식했다. 이 대비는 과제와 대화의 역할 경계가 판단에 영향을 줄 수 있다는 탐색적 증거다. 원래 교육 생성에서는 tools도 학생 요약을 맞다고 인정했으므로 interpret의 실패를 곧바로 원래 대화 경로의 실패율로 해석하면 안 된다.

plain은 한 번 학생이 언급하지 않은 큰 입력의 성질까지 이해했다고 평가했다. tools, finish_only, plain 모두 반복 두 번 중 한 번은 추가 질문을 했다. 현재 출력 방식 중 어느 것도 학습 종료 판단을 안정적으로 보장하지 않았다.

## 조치와 다음 구현 방향

운영 도구를 제거하거나 별도의 해석 LLM 호출을 추가하지 않았다. 실제 학생 발화를 규칙으로 바꾸는 처리도 넣지 않았다. 대화 의미 판별을 별도 호출로 나눠도 이번 결과에서는 판단이 흔들렸고, 호출 지연까지 추가되기 때문이다.

실제 개선안을 시험한다면 같은 한 번의 생성 안에서 최근 교사의 요청과 학생의 응답이 판단 대상임을 명확히 표현하는 작은 입력 변경을 후보로 삼을 수 있다. 다만 wrapped 조건은 판별 과제에서만 시험했으므로, 일반 응답 생성에서도 개선된다고 가정하지 않는다. 망설임·수긍·정확한 요약·오답·중단 요청을 포함한 새 표현으로 검증해야 한다. 현재 근거로 확정된 단일 코드 결함은 없다.

## 재현 및 검증

`PYTHONPATH=apps/backend .venv-app/bin/python scripts/eval_voice_output_modes.py`

추가 자료 표현 조건은 `--mode interpret_wrapped`를 붙인다.

- `voice-output-modes-20260910.jsonl`: 24개 입력·도구 인수·출력 원문
- `voice-output-interpret-wrapped-20260910.jsonl`: 추가 6개 원문
- 검증: 건수·조건별 반복·중복·오류 여부, 원래 대화 메시지 일치, 도구-only 조건의 시스템 일치, Ruff 및 diff 검사.

단일 AI의 비블라인드 원문 검토이며, 일반적인 모델 성능이나 실제 학습 효과로 일반화하지 않는다.
