# 평가 대상과 다음 질문 분리 검증

## 수정

- 발화 입력을 evaluated_turn(방금 질문·기준·학생 답·판정)과 next_turn(다음 목표·질문)으로 분리했다.
- 다음 목표의 정답 기준은 발화 모델에 전달하지 않는다. 정답 판정이 다음 목표까지 이해했다는 뜻으로 섞이지 않게 했다.
- 모델은 120자 이내 피드백만 작성하고, 프로그램이 선택한 실제 다음 질문을 뒤에 붙인다.
- 모델 피드백에 물음표가 있으면 생성 오류로 기록하고 고정 응답을 사용한다.
  이는 표면적 검사이며 물음표 없는 제안·잘못된 칭찬을 차단하지는 않는다.
- 고정 응답도 현재 단계의 질문으로 끝나도록 통일했다.
- 각 학생 답변을 넣기 전에 직전 실제 응답이 해당 확인 질문으로 끝나는지 검사한다.
  다른 질문이면 해당 학생 대사를 주입하지 않고 실패로 기록한다.
- 저장 결과 검사에서도 직전 응답 연결과 다음 질문을 검증한다.
  출력에는 의미적 대화 품질 점수가 아니라는 점을 명시한다.

Ponytail 원칙으로 기존 시제품과 자체 검사를 재사용했으며 새 모델 호출·의존성은 추가하지 않았다.
기존 natural 모드의 평가+피드백 2회 호출은 유지한다. 운영 경로는 변경하지 않았다.

## 검증의 범위

10개 시나리오를 2회 실행했다. 예정 54턴 중 구조·질문 연결 검사 49턴 통과,
근거 검증 오류 2턴, 오류 이후 질문 불일치로 학생 대사 주입을 차단한 3턴이다.
실제 평가 호출은 51회다. 검사 명령은 이 실패를 표시하며 종료 코드 1을 반환한다.
첫 반복의 요약 답에서 모델이 학생 원문 대신 기준 답안을 근거로 복사했고,
두 번째 반복의 “반반” 답에서는 근거 끝에 잘못된 따옴표를 붙였다.
두 경우 모두 원문 일치 검증을 유지하여 진도 이동을 거절했다.
후자의 뒤에 예정됐던 이유·요약 답변 3개는 실제 질문과 맞지 않아 전송하지 않았다.
실행된 턴의 처리 지연 중앙값은 2,835ms이며 ASR/TTS는 제외한다.
자체 검사, Ruff, git diff --check는 통과했다. 발화 품질 및 전체 시나리오는 통과하지 않았다.

실제 질문에 맞는지 확인한 뒤 정해진 합성 학생 답변을 사용하는 제한된 대화 시험이다.
학생이 자유롭게 반응하는 시뮬레이션이나 사람 평가가 아니며,
피드백의 모든 의미적 오류를 자동으로 검증한 것도 아니다.

첫 번째 반복에서는 “각각 0.5겠네” 뒤에 이유 질문이 실제로 출력되고,
그 다음 이유 답변 뒤에는 개념 요약 질문이 출력됐다.
그러나 “그러게·응”에 “정답이 맞아요”라는 잘못된 피드백은 여전히 발생했다.
구조적 혼동을 수정한 사실과 남은 발화 품질 실패를 구분해야 한다.

## 재현

~~~bash
PYTHONPATH=apps/backend:scripts .venv-app/bin/python scripts/eval_voice_stage_controller.py --self-check
PYTHONPATH=apps/backend:scripts .venv-app/bin/python scripts/eval_voice_stage_controller.py --natural
PYTHONPATH=apps/backend:scripts .venv-app/bin/python scripts/eval_voice_stage_controller.py --check-file docs/evaluations/voice-stage-controller-linked-20260910.jsonl
.venv-app/bin/ruff check scripts/eval_voice_stage_controller.py
~~~

현재 검사기는 heard_reply와 실제 질문 연결을 요구하므로 과거 형식 결과 파일은 통과 대상으로 보지 않는다.
자체 검사는 평가/다음 목표 분리, 질문 변경·추가 거절, 발화 길이, 상태 불변성과 단계·중단 처리를 포함한다.
