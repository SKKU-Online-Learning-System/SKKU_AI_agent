2026-09-11 같은 Qwen 9B의 도구·구조화 출력 없는 튜터 대화 실험

결론: Qwen/Qwen3.5-9B는 도구와 JSON 출력 없이 짧은 설명, 오답 수정, 일부 대화 연결을 수행했다. 그러나 자연스러운 소크라틱 교수 행동이 안정적으로 나온다는 결론은 얻지 못했다. 망설임을 정답으로 칭찬하는 문제, 답 선공개, 수치 오류, 종료 뒤 질문이 남았다. 모델·운영 코드·설정은 변경하지 않았다.

**최소 조건**

모델은 Qwen/Qwen3.5-9B 그대로다. voice profile, temperature=0.2, enable_thinking=False, 출력 최대 320토큰을 유지했다. tools=[], force_tools=[]이며 JSON 스키마, finish_turn, 시각화 계획, 학습 단계 분류, 패턴 매칭을 요구하지 않았다. 생성물을 다듬거나 실패한 대화를 좋은 답으로 교체하지 않았다.

사용한 지침은 다음 하나이며 사실 근거를 뒤에 붙였다.

```text
한국어로 학생과 대화하는 친절한 학습 튜터다. 직전 학생의 말에 이어서 짧고 자연스럽게 말하라. 학생이 막히면 작은 도움을 주고 생각할 여지를 남겨라. 질문은 필요할 때 하나만 하고, 설명이나 쉬기를 원하면 그 요청을 존중하라. 아래 자료는 사실 확인용 참고다. 학생에게 할 말만 두세 문장 정도로 답하라.
```

지침 길이와 출력 방식 등을 함께 단순화한 조건이다. 도구 제거만의 순수한 인과 효과라고 해석하지 않는다. 짧게 말하라는 자연어 요청만 있으며 220자 검증이나 출력 수정을 하지 않았다.

**1. 같은 과거 대화에서 40개 초기 응답 비교**

이전 평가의 baseline 첫 요청을 재사용했다. 10개 상황 × tools/plain_minimal × 2회다. 각 비교 쌍의 대화 이력·학생 발화·자료 JSON·토큰 한도를 유지하고 plain 조건에서는 시스템 지침을 위 짧은 지침으로 바꿨다. 과거 시각화 정보가 있는 스냅샷은 그대로 남았지만 새 그림을 요구하거나 만들지는 않았다. 실행 순서는 고정 난수로 섞었다.

| 항목 | 기존 tools 조건 | plain_minimal |
|---|---:|---:|
| 초기 모델 호출 | 20 | 20 |
| 오류 | 0 | 0 |
| 한 호출 소요 시간 중앙값 | 2,932.5ms | 1,235.5ms |
| 그러게/그러게요에 근거 없는 정답 동의 | 4/4 | 4/4 |
| 대기 요청 뒤 재질문 | 2/2 | 0/2 |
| 한 문장 요약 준수 | 2/2 | 2/2 |

주의: 기존 eval_voice_output_modes.py는 초기 모델 호출 하나만 비교한다. tools 조건 중 frustrated 한 번은 search_trusted_web를 선택했고, 이번 비교에서는 검색 이후 최종 답변까지 실행하지 않았다. 따라서 위 시간은 사용자에게 최종 답이 도착하는 시간이나 E2E 음성 지연 비교가 아니다. plain은 20개 모두 비어 있지 않은 일반 텍스트이며 도구 호출은 0이었다.

내용을 직접 읽으면 다음과 같다.

- plain의 대기 응답은 두 번 모두 “네, 알겠습니다. 잠시만 기다려 드릴게요.”로 끝났다. 기존은 두 번 모두 다시 질문했다.
- plain에서도 “그러게요…”에 “맞습니다!”라고 했다. 한 번은 “지금 이 차이를 숫자로 계산해 보려나요?”처럼 어색한 존댓말도 나왔다.
- 분수는 한 번은 구체적인 사과 조각 질문으로 이어졌지만, 다른 한 번은 기존과 같은 “이해하셨나요?”로 끝났다.
- reuse는 한 번은 0.8이 더 크다고 답을 알려줬고, 다른 한 번은 비교 단서와 질문을 남겼다. 해당 두 번째 응답의 “어떤 것이 더 크신가요?”는 부자연스러운 높임 표현이다.
- correct는 한 번은 막연한 다른 문제 적용을 제안했고, 다른 한 번은 “지금 공부하고 계신 내용은 어떤 부분인가요?”로 주제를 다시 물었다.
- ack_repair는 “수식을 보면 훨씬 명확하게 느껴지시나요?” 또는 이미 설명된 수식 재확인으로 돌아갔다.

원시 결과: [40개 초기 응답](voice-plain-comparison-20260911.jsonl).

**2. 실제 교사 응답에 맞춰 이어간 15턴**

소프트맥스 8턴, 분수 7턴의 새 대화를 열었다. 평가자인 Codex가 실제 출력 내용을 읽은 다음 학생 발화를 직접 선택했다. 다음 학생 발화를 모델 생성 전에 미리 고정하지 않았다. 별도 학생 시뮬레이터 모델 호출은 없다. 이는 실제 학생의 학습 성과 측정이 아니라 평가자가 적응적으로 진행한 합성 대화다.

두 세션 모두 같은 최소 지침을 사용했고, 각 주제의 참고 사실은 시작 시 제공하고 유지했다. 대화는 처음부터 끝까지 잘라내지 않고 전달했다. 매 턴 요청에 이전 실제 응답이 정확히 포함되는지 검사했다.

| 세션 | 턴 | 응답 완료 중앙값 | 첫 텍스트 중앙값 |
|---|---:|---:|---:|
| 소프트맥스 | 8 | 2,394.5ms | 485ms |
| 분수 | 7 | 1,935ms | 468ms |

첫 텍스트는 모델 스트림의 첫 텍스트 도착 시간이다. ASR/TTS/브라우저 재생을 포함하지 않는다. 이 대화에는 기존 도구 조건을 동등하게 이어간 대조군이 없으므로 단일 응답 비교와 합쳐 속도나 학습 개선율을 계산하지 않는다.

**소프트맥스 대화**

1. 학생이 지수 함수도 익숙하지 않으니 쉬운 예로 같이 이해하고 싶다고 했다. 교사는 지수값 비율로 설명하고 구체적인 확인 질문 없이 끝냈다.
2. 학생이 “지수 값의 비율이라는 말부터 잘 모르겠어”라고 하자 “2의 지수(2^2)는 4 … 3의 지수(3^3)는 27”을 예로 들었다. softmax의 같은 밑 e를 사용하는 지수 변환과 다른 계산이다.
3. 학생이 “수업에서는 밑이 e로 같다고 본 것 같은데”라고 정정하자 e^2, e^3이 맞다고 바꿨다. 내용은 수정했지만 앞서 잘못 든 예를 명시적으로 인정하기보다 “제가 예시로 든 2와 3은 입력값”이었다고 설명했다.
4. 학생이 두 입력이 2로 같으면 반반이라고 말하자 인정하고 입력이 다르면 어떨지 물었다. 이 부분은 학생 반응에 이어지는 대화였다.
5. 학생이 “하나가 조금 더 크면 그쪽 확률이 조금 더 높아질 것 같아”라고 하자 “입력이 2와 2.1이라면 … 0.5를 훨씬 넘어서게 될 거예요”라고 과장했다.
6. 이에 학생이 “한 0.9쯤?”이라고 오답을 제시하자 0.9는 아니라고 고쳤지만 0.55/0.45 정도라고 말했다. 실제 값은 약 0.524979/0.475021이다. 작은 차이를 과장한 설명에서 비롯된 혼란을 정확한 계산으로 해소하지 못했다.
7. 학생이 앞뒤 설명이 달라 헷갈린다며 핵심 한 문장 정리를 요청하자 한 문장으로 답했지만, softmax의 정규화보다 지수 함수의 비선형성을 설명했다.
8. 명시적인 종료는 질문 없이 받아들였다.

수치는 Python 표준 라이브러리로 확인했다.

```python
import math
assert abs(1 / (1 + math.exp(-0.1)) - 0.52497918747894) < 1e-12
```

**분수 대화**

1. 피자로 같이 배우자고 시작하자 예시를 꺼내고 함께 풀어보자고 물었다.
2. 학생의 “응”에 정답 판정을 하지 않고, 4조각 중 2조각의 분수를 물었다. 이 동의 처리는 적절했다.
3. 학생이 “2분의 1인가?”라고 답하면서 분자·분모를 모르겠다고 하자 2/4=1/2를 인정하고 분자·분모를 설명한 뒤 3조각의 표현을 물었다.
4. 학생이 “위가 4고 아래가 3이야?”라고 틀리자 바로잡았다. 다만 답 3/4를 다 말한 뒤 맞는지 확인하라고 해서 학생에게 남는 사고 과제는 작았다.
5. 학생이 조각 크기가 달라도 같은지 물었을 때는 개수만으로 분수를 정할 수 없다고 정확히 설명했다.
6. 생각할 시간을 달라고 하자 물음표는 없었지만 “어떤 기준으로 나누었는지 한번 더 상상해 보세요”라는 추가 과제를 줬다. 완전한 대기 응답이라고 보기는 어렵다.
7. 학생이 자기 말로 정확히 요약하고 “오늘은 여기까지”라고 했는데 “다음에 또 만나서 … 풀어볼까요?”라고 끝냈다. 강제로 수업을 계속한 정도는 아니지만 명시적인 종료에 불필요한 질문이 붙었다.

원시 요청·응답: [실제 응답을 따라간 15턴](voice-plain-dialogue-20260911.jsonl). 기록의 session으로 두 대화를 구분할 수 있다.

**판단**

단순한 발화 생성에서 일부 장점은 확인된다. 짧은 응답과 빠른 첫 텍스트, 쉬운 주제에서 오답 수정과 후속 질문을 할 수 있다. 그러나 “구조가 복잡해서만 대화가 나빴다”는 설명은 충분하지 않다. 같은 모델이 최소 조건에서도 모호한 동의를 오판하고 정확하지 않은 설명을 하며 학생의 사고 기회를 충분히 남기지 않는다.

이번 최소 조건을 곧바로 운영에 적용하지 않는다. 모델 교체도 하지 않았다. 같은 모델로 후속 실험을 한다면 추상적인 지침을 더 늘리기보다 정확하고 짧은 실제 튜터 대화 예시가 도움이 되는지 좁혀 확인할 수 있지만, 이번에는 그 실험을 수행하거나 효과를 주장하지 않았다.

직접 대화는 새 파일에 시작하고, 다음 호출부터 같은 session/output을 사용하며 evidence는 생략한다.

```bash
PYTHONPATH=apps/backend:scripts .venv-app/bin/python scripts/eval_voice_plain_dialogue.py \
  --output /tmp/new-plain-dialogue.jsonl --session example \
  --student '분수가 뭔지 모르겠어. 피자로 같이 해볼래?' \
  --evidence '피자를 같은 크기 네 조각으로 나누면 한 조각은 1/4, 두 조각은 2/4=1/2이다.'
PYTHONPATH=apps/backend:scripts .venv-app/bin/python scripts/eval_voice_plain_dialogue.py \
  --output /tmp/new-plain-dialogue.jsonl --session example --student '모르겠어. 조금 더 쉽게 도와줘.'
```

self-check는 이전 실제 응답의 다음 요청 포함, 세션별 분리, 원본 요청 불변, tools/force_tools 비활성화를 확인한다. 40개 비교 기록의 입력 쌍과 15턴 이력 연결 검사도 실행해 통과했다. 새 평가 스크립트 두 파일 Ruff 통과. 실제 운영 SAFE/RAG/로그/시각화·음성 통합 검증이나 사람의 청취 평가는 이번 실험 범위에 포함되지 않는다.
