# 음성 대화 개선 평가 — 2026-09-08

모델은 기존 `Qwen/Qwen3.5-9B`를 유지했다. 가중치 학습이나 모델 교체가 아니라
음성 응답 지침, 응답 검증, 후속 질문의 검색 맥락을 수정했다.

## 변경 내용

- 학생 답변·감정에 먼저 반응하고, 정답 확인과 단순 동의를 구분한다.
- 오답에는 작은 반례, 처음 모른다는 답에는 힌트, 반복 혼란에는 단계 설명을 지시한다.
- 학습 발화에 무조건 붙이던 상투적 질문과 새 시각화 강제를 제거했다.
- `고마워, 그런데…`, `잠깐, 회귀라고 했어`를 사회적 발화로 잘라내지 않는다.
- 주제 전환·정정 시 이전 주제 검색을 섞지 않고, `아까`, `방금`은 최근 맥락과 검색한다.
- 실제 대화 기록이 LLM에 전달되는 회귀 테스트를 추가했다.
- 생성 실패를 가짜 칭찬과 학습 질문으로 숨기지 않고 재발화를 요청한다.

고정 기본 정책+소크라틱 정책은 1,440자 → 1,048자다. 과목명, 검색 근거, 대화 기록,
도구 스키마와 `finish_turn` 제출 지침은 이 수치에서 제외했다. 문자 수이며 토큰 수나
응답 지연 감소를 의미하지 않는다. 답변 상한은 기존 feedback 120자 + question 100자를 유지했다.

## 추가 시나리오와 사람 검토 기준

| 시나리오 | 학생 발화 | 기대 행동 |
| --- | --- | --- |
| 감사 뒤 후속 질문 | 고마워, 그런데 왜 합이 1이야? | 감사를 종료로 오해하지 않고 확률 질문에 답한다. |
| 끼어들며 정정 | 잠깐, 집값을 예측하는 회귀 문제라고 했어 | 중단하지 않고 자신의 오해를 인정한 뒤 회귀로 전환한다. |
| 좌절·반복 혼란 | 계속 모르겠어. 나만 못하는 것 같아서 답답해 | 감정을 인정하고 실제 작은 예나 한 단계를 설명한다. |
| 질문 없는 요약 | 질문은 그만하고 한 문장으로 정리해줘 | 평균을 한 문장으로 정리하고 추가 문제를 내지 않는다. |
| 부분적으로 맞는 추론 | 외운 것 같아. 근데 많이 외우면 좋은 거 아니야? | 외웠다는 통찰을 인정하고 일반화와 암기의 차이를 탐색한다. |
| 과제 대필 요구 | 제출할 과제니까 답안 전체를 대신 써줘 | 완성 답안 대신 학생이 진행할 수 있는 도움을 제공한다. |
| 근거 없는 시험 범위 | 교수님이 이번 중간고사에 어디까지 낸대? | 범위를 만들어내지 않고 교수자 공지를 확인하도록 안내한다. |

기존 평균 4턴 연속 대화(`chain_*`)는 실제 직전 모델 응답을 다음 턴에 전달한다.
독립 시나리오는 정해진 직전 질문을 사용한다. 정답·정정·요약·반복 혼란은 질문 없는
설명도 허용하지만, 오답과 첫 혼란에서는 학생에게 작은 판단을 남겼는지 확인한다.

쓰기·웹 검색·TTS는 격리한다. 따라서 이 결과는 ASR 정확도, 음성 억양, 끼어들기,
실제 강의 RAG 검색 품질이나 전체 음성 지연의 검증이 아니다.

자동 검사는 길이, 질문 수, 완전 반복, 시각화 계획, 생성 실패, 일부 잘못된 동조를
검출한다. 의미상 같은 질문의 재탕, 적절한 난이도, 오해 인정, 공감의 자연스러움은
원문을 사람이 검토해야 한다. 자동 `clean`은 교육 품질 점수가 아니다.
전후 표본 수와 검사 규칙이 다르므로 clean 비율로 성능 향상률을 계산하지 않는다.

Python 테스트는 310개 통과했다. 기존 VAD 테스트의 고정 900ms 가정은 테스트 안에서
명시해 실행 환경에 의존하던 실패를 수정했다. 모델 서버 저장소·모델 설정은 변경하지 않았다.
최종 도구 제출 보완 뒤 관련 테스트 87개와 전체 Python Ruff 검사도 통과했다.

## 실제 관찰과 남은 한계

- 정답 `1이요`에 기존에는 새 문제를 자동으로 붙였지만, 후보에서는
  `맞아요, 두 확률의 합은 1입니다.`로 확인하고 질문 없이 마무리했다.
- `잠깐, 집값을 예측하는 회귀 문제라고 했어`에 변경 전에는 `네, 알겠습니다.`로
  끝났다. 변경 후에는 집값·회귀를 이어서 다뤘다. 다만 자신의 오해를 명시적으로
  인정하지 않고 학생에게 이미 확인한 내용을 되묻는 경우가 남았다.
- 좌절 발화에 `답답하시군요`라는 반응은 나왔지만, 구체적인 설명 대신 설명하겠다는
  예고만 하는 경우가 있었다. 공감과 실제 학습 도움을 모두 충족한 것은 아니다.
- 한국어 후보 16개 중 형식 검사 13개 통과, 생성 실패 대체 응답 2개와
  동의 뒤 학습 진행/시각화 검사 실패 1개였다.
- 최종 보완 후 재검증은 8회 중 7회 형식 검사 통과, 좌절 발화 1회에서 긴 일반
  텍스트가 반환되어 안전한 대체 응답을 사용했다. 이 실패를 성공으로 계산하지 않았다.
- 오답 정정이 딱딱하거나 답을 먼저 알려주고 같은 판단을 다시 묻는 사례도 남았다.
  시험 범위를 지어내지는 않았지만, 강의계획서를 실제 받았다고 가정하는 표현도 있었다.

따라서 코드 차원의 맥락 소실·질문 강제는 수정됐지만, 소크라틱 대화와 공감이 모든
상황에서 안정적이라고 결론내릴 수는 없다. 운영 반영 후 실제 학생 음성으로 별도 확인이 필요하다.

## 후속 원인 수정 — 동일 모델 유지

원시 입력·출력은 합성 시나리오에서 `--trace`로 재현했다. 강제 `finish_turn` 요청에도
검색 뒤 일반 텍스트가 반환됐다. 기존 코드는 첫 일반 응답을 검증조차 하지 않고 버렸으며,
재시도에는 실패한 초안과 구체적 오류를 전달하지 않았다. 다시 길게 생성된 응답이
feedback 120자 검증에 걸리면 결국 학생에게 재발화를 요구했다.

수정 사항:

- 일반 텍스트도 기존 음성 계약을 충족하면 첫 응답부터 사용한다. 길이 제한을 늘리거나
  문장을 임의로 잘라내지 않는다. 검증 전에는 텍스트와 음성을 내보내지 않는다.
- 검증 실패 때는 실제 초안과 오류를 모델에 전달해 한 번만 수정한다. 이 내부 수정 대화는
  학생의 대화 이력에 저장하지 않는다.
- 직전 질문과 정확히 같은 질문을 새 피드백 뒤에 붙여도 검출한다. 학생이 질문을 다시
  말해 달라고 명시한 경우에는 허용한다. 의미상 유사한 재질문까지 검출하는 것은 아니다.
- 학생의 정정·반복 좌절이 명시된 경우에만 짧은 현재 턴 지침을 덧붙인다.
- 검색 결과 사용 지침을 조건부로 명확히 했다. 다만 불필요한 검색 선택이 완전히 없어지지는 않았다.

검증 결과:

- 복구 경로 수정 후 [5개 상황 × 3회](voice-natural-repair.jsonl): 생성 실패 0/15.
- 현재 턴 지침 추가 후 [3개 상황 × 3회](voice-natural-context-repair.jsonl): 생성 실패 0/9.
- 전체 Python 테스트 **315개 통과**, 전체 Python Ruff와 `git diff --check` 통과.

정정 시 `제가 잘못 짚었네요`라고 자신의 오해를 인정하는 응답이 재현됐다. 그러나
일부 응답은 정정된 사실을 다시 묻거나, 좌절에 공감한 뒤 예시를 보여주겠다는 말만 한다.
위 24회 무실패는 생성·형식 복구에 대한 결과이며 대화 품질 100%나 실제 음성 전체
경로의 무실패를 의미하지 않는다. 모델·가중치·모델 서버 설정은 그대로다.

## 학생 제보: softmax 질문 뒤 `그러게` — 2026-09-09

직전 질문은 `두 개의 값 2와 3이 있을 때, softmax를 적용하면 어떤 변화가 있을까요?`,
학생 발화는 `그러게`다. 이는 정답을 제시한 발화가 아니므로 `맞아요`로 채점하지 않는다.
짧게 안심시킨 뒤 기존 예시의 더 쉬운 판단으로 이어가는 것을 기대한다.

- 직전 에이전트 질문 뒤 단독 `그러게`, `그러게요`, `글쎄요`, `음`, `잘 모르겠어`는
  망설임 지침을 적용한다. 설명 문장 뒤의 동의나 `그러게, 3이 더 크겠네`처럼 실제 추론을
  포함한 발화는 이 규칙에 넣지 않는다.
- 해당 상황에 정답 칭찬으로 시작하는 응답은 음성 전달 전에 거부하고 기존 교정 경로로 보낸다.
- 프롬프트는 해당 턴에만 짧은 안심·힌트 지침을 덧붙인다. 위로 문장 하나로 답변 전체를
  교체하거나 학생의 말을 매번 같은 문장으로 처리하지 않는다.
- 모델이 완성된 질문까지 feedback에 넣고 question을 비운 경우, 원문을 유지한 채
  마지막 질문을 question으로 옮겨 기존 길이·질문 수 검증을 수행한다.

벤치마크에 표현 4개와 수식 없는 대조군을 추가했다. 수식이 있는 경우는 제보 화면의
softmax 수식·제목·캡션을 기존 시각화로 넣었다. 자동 검사에는 잘못된 정답 칭찬과
안심 표현 누락을 추가했으며, 실제 정답 발화를 오분류하지 않는 회귀 테스트도 포함한다.
단어 기반 검사는 표현 누락의 신호일 뿐 모든 공감 표현을 판정하지는 못한다.

첫 평가 [12회](voice-hesitation.jsonl)에서 3회 형식 실패와 1회 질문 누락이 있었다.
질문 필드 복구와 제보 화면의 수식 맥락을 반영한 재검증은
[voice-hesitation-verified.jsonl](voice-hesitation-verified.jsonl)에 보존한다.

추가 추적에서는 기존 수식을 `reuse`하며 제목까지 보내는 응답을 코드가 거부하는 문제가
확인됐다. 새 시각화를 요청하지 않을 때는 사용하지 않는 `visual_topic`만 비운다.
존재하지 않는 시각화의 재사용은 계속 거부한다. 이후에도 feedback에 질문을 넣는 오류가
있어 망설임 턴 지침을 `짧은 위로 + 쉬운 비교 질문`으로 더 줄였다.

최종 [5개 상황 × 2회](voice-hesitation-compact.jsonl) 결과:

- 잘못된 정답 칭찬 0/10, 안심 표현 누락 0/10, 생성 실패 0/10.
- 쉬운 질문까지 이어진 응답 9/10. `글쎄요` 1회는 위로만 하고 끝나 `question_count`로
  표시했다. 이를 전체 학습 행동 통과로 세지 않았다.
- 실제 `그러게` 응답: `괜찮아요. 같이 천천히 생각해 봐요. 입력 값이 2와 3일 때,
  3이 더 큰 확률을 가질까요?`
- 전체 Python 테스트 326개 통과. 마지막 문구 축약 뒤 음성 계약 48개와 Ruff도 통과했다.

이번 결과는 짧은 망설임을 정답으로 칭찬하는 제보에 대한 회귀 검증이다. 모든 표현과
모든 질문 난이도에 대한 품질 보장은 아니며, 모델은 기존 Qwen/Qwen3.5-9B 그대로다.

## 2026-09-09: 짧은 동의 이후 학습 진행 — 부분 개선, 품질 미달

`그렇겠네`, `그렇겠다고`와 실제 질문에 대한 `응`을 구분하고, 설명 뒤의 동의를
숙달로 취급하지 않도록 했다. 학습 중에는 아직 확인하지 않은 내용을 질문하되,
도움 요청·요약·종료와 학생의 최종 설명에는 질문을 강제하지 않는다.
제보 이력과 실제 생성 답변을 이어 붙이는 7턴 softmax 시나리오를 추가했다.

모델 출력은 feedback 한 필드에 전체 발화를 담도록 단순화했다. 기존 question은
내부 호환용으로만 유지하며, 전체 220자·질문 최대 하나를 발화 전에 검사한다.
내부 learning_step 필드 실험은 출력 실패가 늘어 제거했다. 실패 기록도 보존한다.

최종 코드의 [9회 실모델 기록](voice-learning-compact-verified.jsonl)은 기계적 검사
9/9 통과, 생성 실패 0/9였다. 이는 교육 품질 통과가 아니다. 수동 검토 결과:

- ack_softmax, lesson_ack_again: 숫자만 바꾼 동일한 대소 비교를 반복했다.
- lesson_attempt: 분모의 합과 분자가 같다는 잘못된 설명을 했다.
- lesson_sum: 입력이 1과 2이면 확률 합이 1이 아니라는 잘못된 설명을 했다.
- lesson_stop: 학습 증거가 부족한데도 잘 이해했다고 말했다.

따라서 자연스러운 소크라틱 학습과 수학 정확도는 아직 미달이다. 고정 학생 대본이
생성 질문과 어긋날 수 있다는 평가 한계도 있다. 위 사례는 다음 의미적 회귀 평가에서
반드시 실패로 취급해야 하며, JSONL의 clean 수치를 교육 품질 점수로 사용하면 안 된다.

검증: 내부 계획 실험 상태에서 backend 337개 통과. 해당 필드와 전용 테스트 제거 후
음성 계약·cascade 82개, Ruff, git diff --check 통과. 모델 변경이나 서비스 재시작은
하지 않았다. Ponytail 원칙에 따라 실패한 계획 필드와 별도 상태 관리 계층은 남기지 않았다.

## 후속 수정: 도입 질문 때문에 정상 답변을 버리던 오류

실제 출력 추적에서 `이제 두 입력이 같은 경우를 생각해 볼까요? 입력이 모두 0일 때,
각 출력 확률은 얼마가 될까요?`를 질문 2개로 거부했고, 재시도도 같은 문장을 반환했다.
학생 말의 해석 실패가 아니라 발화 검증이 정상적인 도입 표현까지 거부한 사례다.
공유 검증 경로에서 복수 물음표가 있을 때 `생각해/계산해/확인해/비교해/살펴 볼까요?`
도입 표현만 권유문으로 바꾼다. 서로 다른 실제 질문 두 개는 계속 거부한다.
도구 응답과 일반 텍스트 양쪽에서 재시도 없이 한 번만 음성을 내보내는 회귀 테스트를 추가했다.

단순 동의에 대한 정답 칭찬도 검증에서 거부한다. 소크라틱 지침은 중복 문장을 줄이고
긍정적인 짧은 질문 예시를 사용했다. 별도 학습 상태 계층이나 모델 교체는 하지 않았다.
같은 모델의 추가 교정 호출도 6개 사례로 시험했지만 답 선공개가 남았고 중앙 지연이
약 6.9초여서 채택하지 않았다. 이는 통제된 성능 비교가 아닌 소규모 탐색 결과다.

[도입 표현 수정 평가](voice-learning-invitation-fixed.jsonl): 7개 사례 × 2회에서
생성 실패 0/14, 기계적 검사 12/14. `그렇겠네/그렇겠다고` 4회 모두 정답 선공개 없이
`입력이 모두 2라면 각각의 확률은 얼마가 될까요?`로 이어졌다. 요약 뒤 새 질문 2회는
실패로 기록했다. 단계별 사례의 수학 내용에서는 이전의 출력 합 오류가 관찰되지 않았지만,
계산 대신 '계산해 볼까요'라고 묻거나 답을 설명한 뒤 이유를 묻는 품질 한계는 남았다.

최종 지침의 [연속 대화와 대조군](voice-learning-followthrough.jsonl)은 9회 중 기계적
검사 7회 통과. 반복 질문으로 인한 생성 실패 1회, 요약 뒤 불필요한 질문 1회가 남았다.
계산이 어렵다는 학생에게 소수 계산을 계속 설명하는 난이도 조절도 부족했다.
운영체제 대조군은 확률 주제로 이탈하지 않았다. 이 결과를 전체 학습 품질 통과로 보지 않는다.
모든 평가는 ASR/TTS를 제외한 실제 Qwen/Qwen3.5-9B 호출이며 서비스 재시작은 하지 않았다.

## 모델 주도 방식으로 정리 (사용자 요청)

이 절은 앞선 패턴 기반 발화 보정을 대체한다. local_brain.py는 변경 전 497줄에서
308줄로 줄었다. 망설임·동의·인사·종료 단어 목록, 상황별 프롬프트 분기, 정답 칭찬
차단, 숙달 판정, 반복 질문 차단, 도입 질문 자동 수정, 질문 강제 삽입을 제거했다.
모델의 의도와 문장을 코드가 다시 분류하거나 재작성하지 않는다. 단어별 분기를
다른 모델 판별기나 추가 호출로 옮기지도 않았다.

코드는 스키마·빈 발화·전체 220자 제한·시각화 참조·허용된 도구·재시도·취소만 담당한다.
기존 feedback/question 분리 형식은 발화 내용을 바꾸지 않고 호환한다. 질문 수와
공감·반복·학습 단계의 적절성은 모델 지침 및 오프라인 평가의 책임이다.
일반 텍스트 응답에는 시각화 없는 기본 전달 메타데이터만 붙이며, 학생 의미를 추정하지 않는다.
생성 실패 안내도 학생에게 같은 말을 반복하라고 요구하지 않는 기술 오류 안내로 통일했다.

공통 소크라틱 지침은 8줄의 원칙과 짧은 예시로 정리했다. 기존 모델·220자 발화 예산·
대화 이력·자료·권한 경계는 유지했다. 검색 쿼리 구성의 기존 휴리스틱은 이번 발화 제어
리팩터링 범위 밖이므로 그대로이며, 모든 애플리케이션의 정규식을 없앤 것은 아니다.

이전 회귀 사례를 삭제하지 않고 테스트 책임을 바꿨다. 코드 테스트는 문장을 강제로
고치는 대신 모델 결과·의도·이력을 보존하고 잘못된 형식이 음성으로 새지 않는지 검증한다.
망설임·동의·정정·종료의 교육적 적절성은 기존 실모델 시나리오에 남겼으며, 이전 단어
목록에 없던 표현 5개를 추가했다. 모의 모델 테스트 통과는 교육 품질 통과가 아니다.

검증: backend + ai_rag 테스트 350개, Ruff, git diff --check 통과.
[초기 모델 주도 평가](voice-model-led.jsonl)는 11회 중 기계적 검사 7회 통과였고,
[짧은 예시 보완 평가](voice-model-led-examples.jsonl)는 8회 통과, 생성 실패 0회였다.
이는 각 1회씩의 탐색이며 통계적인 우월성을 의미하지 않는다. 수동 검토에서도:

- `그러게`를 정답으로 칭찬하지 않고, 새로운 휴식 표현에는 마무리했다.
- `오십 퍼센트` 답은 올바르게 해석했다.
- `아직 감이 안 잡혀`에는 공감 없이 답을 먼저 말하고, 이미 주어진 입력을 다시 요구했다.
- 짧은 동의 뒤 기존 설명과 수식을 반복하거나, 구체적 문제 대신 허락을 묻는 경우가 남았다.
- 학생 요약 이후 추가 질문이 남았다.

따라서 구조 변경은 완료했지만 자연스러운 소크라틱 학습 품질까지 보장하지 않는다.
[7턴 연속 평가](voice-model-led-chain.jsonl)에서는 생성 실패는 없었지만, 같은 답변을
그대로 반복한 1회가 검출됐다. 나머지 턴도 대소 비교에 머무는 경향이 있어 학습 진행은
미달이다. 이를 조건문으로 숨기지 않고 후속 모델 품질 평가의 실패 사례로 보존한다.
모델 교체, 추가 추론 호출, 서비스 재시작은 하지 않았다. Ponytail 원칙에 따라
효과가 확인되지 않은 별도 판별기·학습 상태 관리 계층은 추가하지 않았다.

## 완료 기준 재검증: 현재 추론 방식으로는 미달

완료 기준을 형식 검사 통과가 아닌 다음 행동으로 잡았다: 망설임을 정답으로 칭찬하지
않기, 학생의 실제 추론만 이해 증거로 삼기, 이미 확인한 내용에서 구체적인 다음
학습 단계로 진행하기, 자신의 오류를 정정하고 휴식·종료 요청을 존중하기.

Qwen/Qwen3.5-9B를 유지한 채 동일한 핵심 6개 사례(망설임, 동의, 동의의 다른 표현,
학생 요약, 교사 오류 정정, 휴식 요청)를 다음 설정으로 탐색했다. 운영 코드는 바꾸지
않고 평가 프로세스 안에서만 설정과 메시지 구성을 교체했다.

| 실험 | 확인된 미달 사항 |
| --- | --- |
| 추론 활성화, 출력 예산 2048 | 망설임 뒤 계산을 다시 요구하고 요약 뒤 새 시험을 시작함 |
| 도구 없는 직접 발화 | 망설임에 `맞습니다`, 휴식에 근거 없는 이해 칭찬 |
| 이력을 분석 대상 기록으로 전달 | 동의를 정답으로 칭찬하고 동일 계산 질문을 반복함 |
| 한 호출에서 이해 평가·다음 단계 필드를 먼저 생성 | 동의를 이해 증거로 잘못 평가함 |
| 별도 호출로 학생 추론 근거와 계획을 생성 | 근거가 없다고 분석하고도 최종 발화에서 정답 칭찬함 |
| 연속 수업 예시 제공 | 망설임에 정답 칭찬, 다음 질문 반복 |
| 자료 뒤에 교수 지침 배치 | 휴식을 이해 완료로 오인함 |

추가로 추론 활성화 + 자동 도구 선택 + 4096토큰 예산을 핵심 2개 사례에 적용했지만,
`그러게`에 `네, 잘 이해하셨어요`라고 응답했다. 두 호출의 중앙 지연은 약 8.3초였다.
이 실험들도 모델 교체나 단어별 의미 판별 조건문은 사용하지 않았다.

서버가 시스템 지침을 아예 무시하는지도 확인했다. 고정 문자열 응답 지침은 정확히
따랐고 이력 변환 코드에서도 사용자·교사 메시지가 보존됐다. 반면 최소 대화 요청에서도
망설임을 정답으로 해석하는 사례가 나왔다. 이는 현재 추론 설정에서 관찰한 의미 판단
문제이지, 모든 프롬프트 방식이 불가능하다는 증명은 아니다. 효과 없는 실험을 채택하거나
완료로 표시하지 않았다. 형식 검사 점수는 이 의미적 실패를 대신 판정할 수 없다.

추가 학습 가능성은 읽기 전용으로만 점검했다. GPU 6개에서 기존 서비스가 동작 중이며,
GPU 0~4의 여유 메모리는 각각 약 1.7~2.3GiB, GPU 5는 약 15.6GiB였다. 현재 추론 환경에는
peft, trl, datasets가 설치되어 있지 않다. 추가 학습은 별도 환경·학습 데이터·GPU 사용
계획을 정해야 하는 범위 확장이다. 패키지 설치, 모델 학습, 서비스 중단·재시작은 하지 않았다.
