# SKKU i-Campus 역할별 전체 UI 통일 설계

## 목표

현재 프런트엔드의 로그인, 학생, 교수자, 관리자 화면을 실제 성균관대학교
i-Campus와 같은 시각 구조로 통일한다. 역할별 기능과 인증 흐름은 유지하면서,
로그인 이후 각 역할에 맞는 별도 Canvas형 대시보드와 보조 메뉴를 제공한다.

이 설계는 2026-07-11의 `iCampus 통합형 AI 코스 에이전트 디자인`을 대체하지
않는다. 기존 문서의 과목 내부 AI 코스 에이전트 화면은 유지하고, 이번 설계가
실제 인증과 역할별 앱 셸을 그 외곽에 추가한다. 데모용 자유 역할 전환은 실제
인증 화면에서는 노출하지 않는다.

## 승인된 방향

사용자가 승인한 방향은 `역할별 Canvas 화면`이다.

- 로그인 화면은 실제 i-Campus 통합 로그인 화면과 같은 구성으로 표현한다.
- 로그인 이후에는 학생, 교수자, 관리자에게 서로 다른 대시보드를 제공한다.
- 세 역할은 84px 남색 전역 내비게이션, 흰색 상단 바, 연회색 보조 메뉴라는
  공통 구조를 사용한다.
- 전역 내비게이션과 보조 메뉴에 실제 Canvas와 비슷한 선형 아이콘을 표시한다.
- 성균관대학교 문장과 i-Campus 가로형 로고를 로컬 정적 자산으로 사용한다.
- 기존 로그인 API, JWT 저장, 역할 판별, 보호 경로와 역할별 기능은 변경하지
  않는다.

## 기준 화면과 디자인 토큰

기준 화면은 `https://canvas.skku.edu/`의 대시보드,
`https://canvas.skku.edu/courses/73333`의 과목 화면, i-Campus 통합 로그인
화면이다. 브라우저에서 확인한 주요 값은 다음과 같다.

- 전역 내비게이션: 너비 84px, 배경 `#003669`
- 과목 또는 역할 보조 메뉴: 너비 220px, 배경 `#f3f6fb`
- 상단 바: 높이 72px, 흰색 배경, 하단 회색 구분선
- 본문: 흰색 또는 매우 옅은 회색 배경, 24px 기본 내부 여백
- 본문 글자: `#434343` 계열
- 활성 메뉴: 흰색 배경, 남색 글자와 테두리
- 글꼴: Lato 계열을 우선하고 한국어는 시스템 산세리프 글꼴로 대체
- 카드: 4px 안팎의 작은 둥근 모서리와 낮은 그림자
- 표, 폼, 공지 목록: 얇은 회색 구분선과 조밀한 정보 배치

기존 `globals.css`의 `--icampus-*` 변수는 이 기준에 맞게 정리하고, 로그인,
역할별 셸, 과목 내부 에이전트가 동일한 토큰을 공유하게 한다.

## 브랜드 자산

전역 내비게이션에는 현재 저장소의
`apps/frontend/public/skku-logo-white.PNG`을 사용한다. 이 파일은 실제
Canvas 전역 메뉴에서 보이는 흰색 성균관대학교 문장과 같은 형태다.

로그인 화면에는 공식 공개 로그인 페이지의 가로형
`성균관대학교 i-Campus` 로고를 프로젝트 정적 자산으로 저장해 사용한다.
런타임에 외부 URL을 참조하지 않는다. 정적 자산에는 출처와 용도를 식별할 수
있는 파일명을 사용하고, 장식용으로 사용되는 경우 빈 대체 텍스트를, 로그인
화면의 주 로고에는 `성균관대학교 i-Campus` 대체 텍스트를 제공한다.

## 공통 앱 셸

인증된 화면은 다음 세 열 구조를 기본으로 한다.

1. 전역 내비게이션: SKKU 문장, 계정, 대시보드, 과목, 역할별 주요 기능
2. 역할 또는 과목 보조 메뉴: 현재 역할과 컨텍스트에 맞는 세부 기능
3. 본문: 상단 제목 바와 페이지 콘텐츠

전역 내비게이션은 아이콘을 먼저, 짧은 한글 레이블을 아래에 표시한다. 현재
메뉴는 흰색 배경과 남색 아이콘으로 반전한다. 각 아이콘은 기존
`course-agent/ui-icon.tsx`의 `UiIcon`을 공통 컴포넌트 영역으로 이동하거나
재사용 가능하게 확장한다. 새 아이콘을 별도 이미지 파일로 늘리지 않고 동일한
24x24 SVG 선형 체계를 유지한다.

보조 메뉴는 아이콘과 텍스트를 가로로 배치한다. 현재 메뉴는 색상뿐 아니라
테두리, 굵기, `aria-current="page"`로도 표시한다. 상단 바에는 햄버거 메뉴,
현재 화면 또는 과목명, 사용자 이름과 역할, 로그아웃을 배치한다.

## 로그인 화면

로그인 화면은 공식 i-Campus 통합 로그인 화면의 구성을 재현한다.

- 흰색 전체 배경
- 상단의 성균관대학교 i-Campus 가로형 로고
- 로고 아래의 얇은 회색 구분선
- 중앙에 붙어 있는 ID와 Password 입력 영역
- `#4e8e0d` 계열의 초록색 전체 너비 `LOGIN` 버튼
- 하단의 짧은 서비스 안내와 오류 메시지

화면 표기는 i-Campus와 동일하게 유지하되, 실제 입력값은 기존 백엔드 계약에
따라 이메일과 비밀번호로 전송한다. ID 입력의 접근 가능한 레이블에는
`아이디 또는 이메일`을 사용한다. 공식 SSO를 흉내 내는 새 인증 흐름이나 외부
리디렉션은 추가하지 않는다.

로그인 실패, 네트워크 연결 실패, 제출 중 상태는 기존 `ApiError` 처리와
중복 제출 방지를 유지한다. 오류는 입력 영역 가까이에 텍스트와 색상으로
명확히 표시한다.

## 학생 화면

학생의 첫 화면은 실제 Canvas 대시보드처럼 접근 가능한 과목을 카드로
표시한다.

- 전역 메뉴: 계정, 대시보드, 과목, AI 질문, 질문 기록
- 보조 메뉴: 대시보드, 내 과목, AI 질문, 질문 기록
- 본문: 과목 카드 그리드와 최근 질문 또는 할 일 영역

과목 카드는 색상형 상단 영역, 과목명, 학기, 관련 작업 아이콘을 포함한다.
과목 선택 후에는 220px 과목 메뉴에 홈, 강의콘텐츠, AI 코스 에이전트,
질문 기록을 표시한다. 기존 학생 챗봇, 출처 표시, 자료 부족 안내, SAFE
가드레일은 시각 변경 후에도 그대로 유지한다.

## 교수자 화면

교수자의 첫 화면은 담당 과목과 자료 운영 상태를 중심으로 구성한다.

- 전역 메뉴: 계정, 대시보드, 담당 과목, 자료, 질문 로그
- 보조 메뉴: 홈, 강의자료, 질문 로그, AI 설정
- 본문: 담당 과목 카드, 최근 업로드, 처리 상태, 최근 학생 질문

담당 과목에 들어가면 과목명과 학기를 상단에 표시하고, 자료 업로드, 자료
목록, 질문 로그, AI 응답 정책으로 이동할 수 있다. 기존 파일 검증, 처리 상태,
과목 접근 권한과 API 요청은 유지한다.

## 관리자 화면

관리자의 첫 화면은 전체 운영 지표와 관리 작업을 중심으로 구성한다.

- 전역 메뉴: 계정, 대시보드, 과목, 사용자, 자료, 로그
- 보조 메뉴: 운영 현황, 과목 관리, 사용자 관리, 자료, 로그
- 본문: 활성 과목, 사용자, 자료, 질문 로그 요약과 최근 관리 활동

기존 관리자 과목 목록, 필터, 생성·수정, 활성화·비활성화 기능은 Canvas형 표와
폼으로 다시 표현한다. 정보 밀도와 기존 동작을 유지하며, 모바일에서 표는
가로 스크롤을 허용한다.

## 컴포넌트 경계

구현은 다음 단위로 분리한다.

- `IcampusLogo`: 가로형 로그인 로고와 흰색 문장의 올바른 대체 텍스트 처리
- `GlobalNavigation`: 역할별 전역 메뉴, 아이콘, 활성 경로
- `ContextNavigation`: 역할 또는 과목별 보조 메뉴
- `IcampusTopbar`: 현재 제목, 사용자 정보, 로그아웃, 메뉴 접기
- `RoleDashboard`: 역할별 첫 화면의 공통 제목과 로딩·오류·빈 상태
- `CourseCard`: 학생·교수자 대시보드에서 공유하는 Canvas형 과목 카드
- 기존 `AppShell`: 위 컴포넌트를 조합하는 인증된 화면의 공통 진입점

메뉴 데이터는 `lib/auth.ts`에서 역할별 `href`, 레이블, 아이콘 이름을 함께
제공한다. 역할과 경로 판별은 기존 `ProtectedRoute`와
`getRoleHomePath`를 사용한다. 화면 컴포넌트가 인증 토큰이나 역할을 별도로
판단하지 않게 한다.

## 상태와 데이터 흐름

1. 사용자가 로그인 폼을 제출한다.
2. 기존 `loginRequest`가 백엔드에 이메일과 비밀번호를 전송한다.
3. `AuthProvider`가 토큰과 사용자 역할을 저장한다.
4. `getRoleHomePath`가 학생, 교수자, 관리자 대시보드로 이동시킨다.
5. `AppShell`이 역할별 전역 메뉴와 보조 메뉴를 구성한다.
6. 각 페이지는 기존 API 클라이언트를 통해 과목, 자료, 사용자 데이터를
   조회한다.

디자인 변경으로 API 요청 형식, 백엔드 권한 검증, 토큰 저장 방식,
역할별 접근 제어를 수정하지 않는다.

## 오류, 로딩과 빈 상태

- 인증 확인 중: Canvas형 중앙 로딩 화면을 표시한다.
- 로그인 실패: 입력 영역 아래에 명확한 오류와 재시도 가능 상태를 표시한다.
- API 연결 실패: 기존 네트워크 오류 메시지를 역할 대시보드 안에 표시한다.
- 과목 없음: 역할별 설명과 가능한 다음 행동을 보여준다.
- 자료 없음 또는 처리 실패: 상태 배지와 업로드 또는 재시도 안내를 표시한다.
- 권한 없음: 보호 경로가 역할 홈으로 이동시키며 이유를 스크린리더에 알린다.
- 긴 과목명: 한 줄 말줄임과 전체 이름 확인 수단을 제공한다.

## 반응형과 접근성

- 데스크톱: 84px 전역 메뉴, 220px 보조 메뉴, 유동 본문을 유지한다.
- 태블릿: 보조 메뉴를 접을 수 있고 본문 카드 열 수를 줄인다.
- 모바일: 전역 메뉴를 상단 가로 메뉴로 바꾸고 보조 메뉴를 접힌 탐색 영역으로
  전환한다.
- 모든 아이콘 메뉴에는 화면에 보이는 레이블과 접근 가능한 이름이 있다.
- 메뉴 현재 상태는 `aria-current`, 색상, 배경과 테두리로 함께 전달한다.
- 메뉴 접기, 로그아웃, 카드 링크와 폼은 키보드로 사용할 수 있어야 한다.
- 포커스 표시와 축소 동작 설정을 유지한다.

## 구현 범위에서 제외

- 성균관대학교 SSO 또는 실제 Canvas 계정 연동
- 로그인 API와 JWT 구조 변경
- 백엔드 역할과 권한 정책 변경
- 새로운 교수자 또는 관리자 API 구현
- Canvas의 캘린더, 메시지함, 알림 기능 전체 복제

전역 메뉴에는 현재 제품에서 동작하는 기능만 연결한다. Canvas에 존재하지만
구현되지 않은 메뉴를 단순 장식으로 추가하지 않는다.

## 검증 기준

- 로그인 화면이 공식 i-Campus 로그인 화면의 로고, 입력 구조, 버튼 색상과
  여백을 재현한다.
- 학생, 교수자, 관리자 로그인 후 각각 올바른 역할 대시보드로 이동한다.
- 세 역할의 전역·보조 메뉴에 선형 아이콘과 텍스트가 함께 표시된다.
- 현재 경로가 전역 메뉴와 보조 메뉴 양쪽에서 올바르게 강조된다.
- 기존 로그인 실패와 네트워크 실패 테스트가 계속 통과한다.
- 보호 경로와 잘못된 역할 접근 테스트가 계속 통과한다.
- 과목, 자료, 관리자 기능의 기존 상호작용 테스트가 계속 통과한다.
- 데스크톱, 태블릿, 모바일에서 메뉴와 콘텐츠가 겹치지 않는다.
- 키보드 탐색, 포커스 표시, 접근 가능한 이름을 확인한다.
- `npm.cmd test --workspace @skku-course-agent/frontend`를 통과한다.
- `npm.cmd run typecheck`, `npm.cmd run lint`,
  `npm.cmd run build:frontend`를 통과한다.
- 로컬 개발 서버를 Chrome으로 열어 로그인과 세 역할별 핵심 경로를 시각적으로
  확인하고 콘솔 오류가 없는지 점검한다.
