# Canvas형 코스 에이전트 프런트엔드 기반 설계

## 목표

첨부 PRD의 학생, 교수자, 관리자 필수 화면을 탐색 가능한 프런트엔드 목업으로 구현한다. 기존 I-Campus형 코스 에이전트 디자인을 유지하고, 실제 Canvas 페이지에서 확인한 레이아웃과 시각 규칙을 따른다. 백엔드 연동은 이후 인증, 과목, 자료, 채팅, 로그, 통계 단위로 교체할 수 있어야 한다.

## 범위

- 학생: 로그인, 접근 가능 과목, 코스 에이전트, 답변 출처, 최근 대화
- 교수자: 담당 과목, 자료 업로드와 처리 상태, 에이전트 활성화, 응답 정책, 질문 로그
- 관리자: 통계 대시보드, 과목 관리, 사용자와 권한, 전체 자료, 전체 로그
- 공통: 개발용 역할 전환, 브레드크럼, 반응형 내비게이션, 로딩·빈 상태·오류·권한 없음 표현

실제 인증, 서버 저장, RAG 호출, 문서 처리, CSV 다운로드는 이 단계에서 구현하지 않는다. 해당 동작은 명확한 데모 상태와 안내 메시지로 표현한다.

## 디자인 기준

Canvas 실측 기준을 사용한다.

- 84px 남색 글로벌 내비게이션 (`#003669` 계열)
- 220px 연한 회색 과목·영역 내비게이션 (`#f3f6fb` 계열)
- 약 64px 높이의 흰색 브레드크럼 헤더
- 흰색 중심 콘텐츠, 얇은 회색 경계, 작은 모서리 반경
- 청록색 선택 테두리와 남색 강조색
- Lato, Helvetica, Arial 계열 글꼴과 16px 기본 본문
- 대시보드는 넓은 본문과 좁은 우측 상태 패널
- 목록은 상단 검색·필터와 접이식 구획 구조

모바일에서는 글로벌 내비게이션을 상단 바로 축소하고 보조 내비게이션을 서랍으로 전환한다.

## 구조

단일 `AppShell`이 글로벌 내비게이션, 보조 내비게이션, 브레드크럼을 소유한다. 개발용 역할 전환은 학생, 교수자, 관리자 중 하나를 선택한다. 역할별 메뉴 정의와 현재 화면 ID를 이용해 본문 컴포넌트를 교체한다.

초기 단계에서는 단일 Next.js 페이지 안의 화면 레지스트리를 사용한다. URL이 필요한 시점에는 화면 ID를 App Router 경로로 치환할 수 있도록 화면 컴포넌트는 셸과 분리한다. 역할별 앱이나 불필요한 추상화는 만들지 않는다.

## 화면 구성

### 학생

- 로그인 목업은 학교 계정과 서비스 계정 진입점을 보여준다.
- 과목 목록은 과목명, 교수자, 학기, 활성 상태를 표시한다.
- 코스 에이전트는 질문, 답변, 자료 기반 여부, 출처 문서와 페이지, 자료 부족 경고, SAFE 안내를 제공한다.
- 최근 대화는 질문, 답변 요약, 생성 시각을 표시하고 선택 시 대화를 복원한다.

### 교수자

- 대시보드는 담당 과목, 자료 처리 상태, 최근 질문을 요약한다.
- 자료 화면은 PDF, PPTX, DOCX, TXT 업로드와 처리 상태를 보여준다.
- 설정 화면은 에이전트 활성화와 응답 정책을 변경한다.
- 로그 화면은 과목, 기간, 검색어 필터를 제공하며 학생 식별 정보는 최소화한다.

### 관리자

- 대시보드는 사용자, 활성 과목, 질문, 출처 포함률, 평균 응답 시간 등 PRD 지표를 표시한다.
- 과목 화면은 등록, 수정, 활성 상태 변경 목업을 제공한다.
- 사용자 화면은 검색, 역할 필터, 역할 변경 목업을 제공한다.
- 자료 화면은 처리 상태 확인과 재처리·삭제 목업을 제공한다.
- 로그 화면은 기간, 과목, 역할, 사용자 필터와 모델·응답 시간 정보를 표시한다.

## 상태와 데이터 경계

데모 데이터는 역할별 과목, 자료, 대화, 로그, 통계를 한 모듈에 둔다. reducer는 활성 역할, 현재 화면, 필터, 토글, 업로드와 메시지 상태만 관리한다. 기존 공유 도메인 타입을 우선 재사용하고, 프런트엔드 전용 표현 타입만 로컬에 추가한다.

향후 API 교체 경계는 인증, 과목, 자료, 채팅, 로그, 통계다. 화면은 이 데이터 형태를 소비하므로 데모 데이터 대신 API 응답을 주입할 수 있다. 이 단계에서는 별도 API 클라이언트 계층을 미리 만들지 않는다.

## 오류, 안전, 접근성

- 로딩, 빈 목록, 권한 없음, 자료 부족, 업로드 실패 상태를 제공한다.
- 업로드 확장자와 크기 검증은 현재 규칙을 유지한다.
- 출처가 없으면 강의자료에서 확인된 내용이 부족함을 표시한다.
- 과제·시험 정답 요청은 힌트와 개념 중심 안내로 전환한다.
- AI 답변이 학습 보조용임을 항상 알린다.
- 키보드 탐색, 폼 레이블, `aria-current`, `aria-live`, 상태 텍스트와 충분한 색 대비를 적용한다.

## 검증

- reducer, 역할별 메뉴, 필터, 자료 선택, 업로드 검증 단위 테스트
- `npm run lint`
- `npm run typecheck`
- 프런트엔드 테스트 명령
- `npm run build:frontend`
- 로컬 브라우저에서 학생·교수자·관리자 전체 탐색, 폼 동작, 데스크톱·모바일 레이아웃 확인

완료 기준은 모든 필수 화면을 역할 전환과 메뉴로 탐색할 수 있고, 주요 데모 상호작용이 동작하며, 위 정적 검사·테스트·빌드·브라우저 검증을 통과하는 것이다.
