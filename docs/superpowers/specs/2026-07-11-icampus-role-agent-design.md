# iCampus 통합형 AI 코스 에이전트 디자인

## 목표

기존 SKKU 코스 에이전트 프론트엔드를 실제 성균관대학교 iCampus 강의실과 같은 시각 구조로 재설계한다. iCampus의 글로벌 메뉴, 과목 메뉴, 상단 과목명 영역을 유지한 채 과목 메뉴에 `AI 코스 에이전트`를 추가한다. 사용자는 학생과 교수 화면을 자유롭게 전환하며 각 역할에 맞는 RAG 설정과 채팅 기능을 사용할 수 있다.

이 단계는 프론트엔드 데모를 대상으로 한다. 역할 전환은 인증 권한과 연결하지 않으며, 학생과 교수 사이를 자유롭게 전환할 수 있어야 한다.

## 기준 화면과 시각 원칙

기준 화면은 `https://canvas.skku.edu/courses/74240`의 iCampus 강의실 홈이다. 다음 구조를 재현한다.

- 약 84px 너비의 남색 글로벌 내비게이션
- 성균관대학교 심볼과 아이콘 중심 글로벌 메뉴
- 약 220px 너비의 연회색 과목 내비게이션
- 햄버거 메뉴와 과목명이 있는 흰색 상단 바
- 그림자와 과도한 둥근 모서리를 줄인 평평한 흰색 본문
- 얇은 회색 구분선, 작은 제목, 조밀한 정보 배치
- iCampus와 비슷한 남색, 청록색 포인트, 회색 배경과 본문색

과목 내비게이션에는 `홈`, `강의콘텐츠`, `출결현황`, `성적`, `AI 코스 에이전트`를 표시한다. `AI 코스 에이전트`는 선택된 상태로 표현한다.

## 공통 화면 구조

상단 과목명 오른쪽에 `학생 | 교수` 세그먼트 토글을 배치한다. 토글은 키보드로 조작할 수 있고 현재 역할을 명확히 표시해야 한다. 역할을 바꾸더라도 iCampus 외곽 구조와 과목 정보는 유지한다.

AI 코스 에이전트 본문은 다음 세 영역으로 구성한다.

1. 상단 안내 영역: 역할, 에이전트 상태, 자료 기반 답변 원칙을 표시한다.
2. 중앙 채팅 영역: 역할별 대화 내역, 사용자 질문, AI 답변, 답변 출처를 표시한다.
3. 오른쪽 설정 및 자료 영역: 역할에 따라 교수용 자료 제어 또는 학생용 성격과 첨부 파일 제어를 표시한다.

질문 입력 영역은 본문 하단에 유지한다. 파일이 첨부되었거나 교수가 참고 자료를 선택한 경우 입력창 위에 현재 컨텍스트를 요약한다.

학생과 교수의 대화 내역, 선택값, 첨부 파일 목록은 서로 독립적으로 관리한다. 역할을 전환했다가 돌아오면 해당 역할의 상태가 유지되어야 한다.

## 교수 화면

교수 화면에서도 AI와 직접 채팅할 수 있다. 교수는 AI가 참고할 자료를 명시적으로 제어한다.

### 기존 강의콘텐츠 선택

- 교수가 업로드한 강의콘텐츠 목록을 체크박스로 표시한다.
- 각 항목에는 문서명, 파일 형식, 처리 상태를 표시한다.
- `준비됨` 상태인 자료만 RAG 참고 대상으로 선택할 수 있다.
- `처리 중` 또는 `실패` 상태는 선택할 수 없으며 그 이유를 표시한다.
- 전체 선택과 전체 해제를 제공한다.

### 추가 참고 문서 첨부

- 교수는 AI 코스 에이전트 전용 참고 문서를 추가할 수 있다.
- 데모에서는 파일 선택과 목록 표시까지 프론트엔드 상태로 구현한다.
- PDF, PPTX, DOCX, TXT 형식을 허용하고 파일당 최대 크기는 20MB로 제한한다.
- 허용 형식과 크기 안내를 표시하며, 조건을 벗어난 파일은 오류 메시지로 거절한다.
- 첨부 문서는 삭제할 수 있고 처리 상태를 표시한다.

### 교수 RAG 채팅

- 선택된 기존 강의콘텐츠와 추가 첨부 문서를 현재 RAG 범위로 표시한다.
- AI 답변에는 사용한 문서명과 페이지 또는 섹션 정보를 표시한다.
- 참고할 자료가 없으면 질문 전송을 막지 않되, 자료가 선택되지 않았다는 경고와 자료 부족 답변 예시를 제공한다.

## 학생 화면

학생 화면에서도 AI와 직접 채팅할 수 있다. 학생은 답변 성격과 질문에 함께 보낼 파일을 설정할 수 있다.

### AI 성격 선택

현재 ChatGPT 공식 성격 구성을 참고하여 다음 7가지를 제공한다.

- 기본: 명확하고 중립적
- 전문적: 정교하고 격식 있는 설명
- 친근함: 따뜻하고 대화하듯 설명
- 솔직함: 핵심과 개선점을 직접 제시
- 개성 있음: 창의적인 비유와 가벼운 유머 활용
- 효율적: 짧고 빠르게 핵심만 설명
- 냉소적: 건조한 유머를 섞되 실용적으로 답변

성격은 말투와 설명 방식만 바꾼다. 자료 우선 사용, 출처 표시, SAFE 가드레일, 과제 및 시험 정답 제한에는 영향을 주지 않는다.

### 파일 및 이미지 첨부

- 학생은 질문에 문서 파일과 이미지를 첨부할 수 있다.
- 데모에서는 파일 선택, 미리보기 또는 파일 정보 표시, 제거를 프론트엔드 상태로 구현한다.
- 이미지에는 썸네일과 대체 텍스트를 제공한다.
- PDF, DOCX, TXT, PNG, JPG, JPEG 형식을 허용하고 파일당 최대 크기는 10MB로 제한한다.
- 허용하지 않는 형식이나 크기는 전송 전에 오류로 표시한다.

### 학생 RAG 채팅

- AI는 해당 과목에서 교수가 허용한 자료를 우선 사용한다.
- 학생이 첨부한 파일과 이미지는 현재 질문의 보조 컨텍스트로 표시한다.
- 답변에는 자료 기반 여부와 출처를 표시한다.
- 과제나 시험 정답 요청은 정답 대신 개념, 접근 방법, 단계별 힌트로 전환한다.

## 상호작용과 상태

초기 역할은 학생이다. 역할 토글, 학생 성격, 교수 자료 선택, 역할별 채팅과 첨부 목록은 클라이언트 상태로 관리한다. 새로고침 뒤에도 유지할 필요가 있는 역할 및 설정은 `localStorage`에 저장하며, 브라우저 저장소를 사용할 수 없는 환경에서는 기본값으로 안전하게 복구한다.

질문 전송은 빈 질문이면서 첨부도 없는 경우 비활성화한다. 전송 중에는 중복 제출을 막고 진행 상태를 표시한다. 데모 응답은 기존 정적 채팅 데이터 형태를 유지하되 선택한 역할, 성격, 자료와 첨부 상태가 화면에 명확히 반영되어야 한다.

## 오류 및 빈 상태

- 채팅 없음: 역할에 맞는 시작 안내와 예시 질문을 표시한다.
- 자료 없음: 교수에게 자료 선택 또는 첨부 방법을 안내한다.
- 자료 처리 중 또는 실패: 상태와 다음 행동을 함께 표시한다.
- 잘못된 첨부: 형식 또는 크기 문제를 입력 영역 가까이에 표시한다.
- 자료 부족 답변: 일반 답변과 구별되는 경고 스타일과 문구를 사용한다.
- 비활성 과목: 입력을 비활성화하고 교수자 안내를 따르도록 표시한다.

## 접근성과 반응형 동작

- 모든 아이콘 버튼에 접근 가능한 이름을 제공한다.
- 역할 토글, 성격 선택, 자료 체크박스, 첨부 제거를 키보드로 사용할 수 있어야 한다.
- 선택 상태는 색상뿐 아니라 텍스트, 테두리, ARIA 상태로도 전달한다.
- 데스크톱에서는 실제 iCampus 비율과 정보 밀도를 우선한다.
- 태블릿에서는 오른쪽 설정 영역을 채팅 아래로 이동한다.
- 모바일에서는 글로벌 메뉴를 가로 스크롤형으로, 과목 메뉴를 접을 수 있는 영역으로 전환한다.

## 구현 경계

이번 작업은 `apps/frontend`의 화면과 클라이언트 상호작용을 대상으로 한다. 실제 인증 권한, 파일 업로드 API, 문서 인덱싱, RAG 요청 API는 새로 구현하지 않는다. 다만 이후 백엔드 연결이 가능하도록 역할, 성격, 선택 문서, 첨부 파일을 명확한 상태 단위로 분리한다.

기존 `packages/shared`의 도메인 타입과 현재 프론트엔드 데이터 구조는 가능한 한 유지한다. 화면 재설계를 위해 필요한 프론트엔드 전용 타입은 컴포넌트 가까이에 두고 백엔드 계약처럼 가장하지 않는다.

## 검증 기준

- 실제 iCampus 기준 화면과 글로벌 메뉴, 과목 메뉴, 상단 바, 색상, 선, 여백을 시각 비교한다.
- 학생과 교수 토글이 자유롭게 동작하고 역할별 상태가 섞이지 않는지 확인한다.
- 교수 자료 선택, 전체 선택, 추가 문서 첨부와 제거를 확인한다.
- 학생의 7개 성격 선택, 파일 및 이미지 첨부와 제거를 확인한다.
- 두 역할에서 채팅 입력과 전송 상태가 동작하는지 확인한다.
- 출처, 자료 부족, SAFE 안내가 역할과 관계없이 유지되는지 확인한다.
- 키보드 조작과 좁은 화면 레이아웃을 확인한다.
- `npm run typecheck`, `npm run lint`, `npm run build:frontend`를 통과한다.
- 로컬 개발 서버를 Chrome으로 열어 콘솔 오류와 주요 상호작용을 최종 확인한다.
