# 과목 중심 역할별 대시보드 설계

## 목적

학생, 교수자, 관리자 대시보드의 본문을 기능 바로가기 카드가 아니라 실제 과목
목록으로 구성한다. 로그인 직후 사용자는 자신의 역할에 맞는 과목을 바로 확인하고,
관리자는 대시보드에서 전체 과목 관리 작업을 수행할 수 있어야 한다.

이 문서는 기존 `2026-07-21-skku-icampus-role-ui-design.md`의 시각 구조를 유지하면서
대시보드 콘텐츠 의미를 교정한다.

## 역할별 대시보드

### 학생

- `/student`에서 수강 가능한 활성 과목 목록을 표시한다.
- 기존 `CourseListClient`를 `audience="student"`로 재사용한다.
- 로딩, 빈 목록, API 오류, 과목 상태 표시는 기존 `/student/courses` 동작을 유지한다.

### 교수자

- `/professor`에서 담당 교수자로 등록된 과목 목록을 표시한다.
- 기존 `CourseListClient`를 `audience="professor"`로 재사용한다.
- 로딩, 빈 목록, API 오류, 과목 상태 표시는 기존 `/professor/courses` 동작을 유지한다.

### 관리자

- `/admin`에서 전체 과목 관리 화면을 표시한다.
- 기존 `AdminCoursesClient`를 재사용한다.
- 검색, 학기·담당 교수·상태 필터, 새 과목 등록, 수정, 활성화·비활성화 기능을
  모두 유지한다.

## 경로와 내비게이션

- `/student/courses`, `/professor/courses`, `/admin/courses` 경로는 삭제하거나
  리다이렉트하지 않고 기존 기능 경로로 유지한다.
- 역할별 홈 링크와 대시보드 메뉴는 계속 역할 홈 경로를 가리킨다.
- 상단 제목은 홈 경로에서 `대시보드`, 과목 경로에서 기존 역할별 과목 메뉴명을
  표시한다.
- 인증, JWT, `ProtectedRoute`, 역할별 접근 범위는 변경하지 않는다.

## 컴포넌트 정리

- 세 역할 홈 페이지가 기존 과목 목록 컴포넌트를 직접 렌더링한다.
- 더 이상 사용하지 않는 `RoleDashboard`, `DashboardAction`, 관련 테스트와 전용 카드
  스타일을 제거한다.
- 과목 목록 컴포넌트 자체의 데이터 요청이나 상태 관리 로직은 변경하지 않는다.

## 오류와 빈 상태

- 학생·교수자 대시보드는 `CourseListClient`의 기존 오류 메시지와 빈 상태 문구를
  그대로 사용한다.
- 관리자 대시보드는 `AdminCoursesClient`의 기존 로딩, 오류, 필터 결과 없음 상태를
  그대로 사용한다.
- 새로운 API 호출이나 대체 데이터는 추가하지 않는다.

## 테스트와 완료 조건

- 학생 홈이 학생용 `CourseListClient`를 렌더링한다.
- 교수자 홈이 교수자용 `CourseListClient`를 렌더링한다.
- 관리자 홈이 전체 `AdminCoursesClient`를 렌더링한다.
- 홈 화면에 기존 기능 바로가기 카드가 남지 않는다.
- 기존 과목 경로와 과목 목록·관리 테스트가 계속 통과한다.
- 프런트엔드 테스트, 타입 검사, 린트, 프로덕션 빌드가 통과한다.
